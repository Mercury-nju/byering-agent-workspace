# Byering 行业任务测试题

**适用对象**：对 AI Agent、内容研究、增长运营、产品策略、自动化工作感兴趣的学生候选人  
**测试目的**：筛选能够从真实业务问题出发，使用 AI 和公开信息完成研究、判断、设计与复盘的人才。  
**建议完成时间**：任选 1 题为基础要求；优秀候选人可挑战第 1 题。  
**提交形式**：Markdown / PDF / Notion 均可，必要时附 Excel、截图、链接或可运行 Demo。

> 本测试不以“答案是否完美”作为唯一标准。我们更关注：问题定义是否清楚、证据是否真实、判断是否有逻辑、方案是否能执行、是否知道边界，以及能否借助 AI 提高工作质量。

## 一、候选人统一作答要求

### 1. 必须区分事实、推断与建议

请使用以下标签：

- **事实**：能够由链接、截图、原始数据或公开资料直接验证。
- **推断**：基于事实进行的判断，并写出推理依据。
- **建议**：下一步应该采取的行动。

### 2. AI 使用要求

可以使用任何 AI 工具，但必须提交简短的 **AI 使用记录**：

| 项目 | 内容 |
|---|---|
| 使用的工具 / 模型 |  |
| 主要用于什么环节 | 搜索 / 整理 / 分析 / 写作 / 代码 / 其他 |
| 一个关键 Prompt 或操作说明 |  |
| AI 输出中发现并修正的问题 |  |
| 最终由自己确认的内容 |  |

禁止把未经核验的 AI 生成内容当作事实提交。不得提交个人隐私、账号密码、企业机密或未获授权的数据。

### 3. 统一评价目标：OPR / SOP

每道题都需要回答：

- **OPR（Outcome / Problem / Reason）**：希望产生什么结果、解决什么问题、为什么值得解决？
- **SOP（Standard Operating Procedure）**：如果这个任务重复发生，别人能否按照你的步骤复现？

## 二、任务总览

| 任务 | 难度 | 主要考察 | 建议提交物 |
|---|---:|---|---|
| 任务一：垂直行业智能获客方案 | 高 | 行业理解、问题定义、多 Agent 设计、业务闭环 | 一页式案例 + 方案说明 + 验收设计 |
| 任务二：抖音爆款作品评论区机制拆解 | 中 | 内容研究、评论分析、证据意识、结构化表达 | 作品分析报告 + 评论样本表 |
| 任务三：高意向用户识别与首触设计 | 基础 | 线索判断、优先级、个性化沟通、风险边界 | Prospect Brief + 触达方案 |

# 任务一：垂直行业智能获客方案

## 任务说明

请选择一个你熟悉或愿意研究的垂直行业，例如汽车、医美、房地产、教育、招聘、企业服务、本地生活或电商。请围绕该行业中的一个具体获客问题，设计一套能够由主 Agent 协同多个专业 Agent 执行的最小可验证方案。

你不需要设计完整产品，也不要求把所有环节都自动化。重点是说明：**谁在什么场景下，给系统什么输入，系统如何发现和判断潜客，最终如何推动一次合适的业务动作。**

## 输入条件

候选人可自行设定，但必须明确写出：

- 目标行业、业务角色和具体业务对象；
- 目标客户是谁，以及什么行为能够说明其有需求；
- 公开可获取的数据来源，例如抖音作品、评论、主页、搜索结果、官网、门店信息等；
- 业务目标，例如获得咨询、预约到店、留资、复购或完成一次有效触达；
- 不得使用的敏感数据与必须人工确认的动作；
- 至少 1 个真实或公开可验证的行业案例作为依据。

## 期待输出

请按以下结构提交：

### A. 一页式任务定义

建议直接套用《企业需求拆解·一页式案例样本模板》的 01—08 节，但内容应改写为你的候选方案。至少包含：

1. 任务名称 / 行业 / 使用角色；
2. 最小任务闭环：当什么发生时，谁使用什么输入，经过哪些处理，得到什么输出，由谁决定是否采用；
3. 当前做法与失败模式；
4. 第一版包含与暂不包含的范围；
5. 数据、权限、隐私与人工接管边界。

### B. Agent / Skill 协作图

至少设计以下角色中的 3 个，并说明输入、输出、依赖关系和失败时如何交接：

- 获客策略师：把业务目标转成客户画像、搜索范围和意向信号；
- 线索猎人：搜索或收集候选账号、作品或企业；
- 客户研究员：整理资料、提炼需求信号和切入点；
- 线索分析师：去重、评分、排序并附证据；
- 触达策略师：制定首触方式、话术和下一步动作；
- 风控专员：检查重复触达、权限、频控、勿扰和风险。

### C. 一次完整运行示例

使用一个脱敏或公开样例，展示：

```text
业务目标 → 搜索 / 数据输入 → 候选发现 → 证据核验 → 意向评分
→ 触达策略 → 人工审批点 → 执行动作 → 结果记录 → 后续跟进
```

### D. 验收指标与测试集

至少定义：

- 3 个可逐条检查的合格标准；
- 3 个不可接受的错误或红线；
- 一个最小测试集设计，说明需要多少条正例、负例和边界案例；
- 结果如何衡量准确性、完整性、可解释性、时延或成本；
- 如果只能优化一件事，优先优化什么，为什么。

## 核心评判标准

| 评判维度 | 权重 | 好的表现 |
|---|---:|---|
| 问题真实度与聚焦程度 | 20% | 不是泛泛地说“提高效率”，而是锁定一个高频、可验证的业务动作 |
| 行业洞察 | 20% | 能说明行业角色、购买信号、决策链和实际约束 |
| Agent 协作设计 | 20% | 每个 Agent 边界清楚，有输入输出、依赖、交接和失败处理 |
| 业务闭环 | 15% | 从发现一直连接到触达、跟进或业务结果，而不是只做分析报告 |
| OPR / SOP 与验收 | 15% | 目标、步骤、标准、测试集和人工接管点可复现 |
| 证据、风险与边界 | 10% | 事实可追溯，知道隐私、平台规则和误触达风险 |

### 重点观察信号

- 能否把“大方向”收敛成一个最小可验证任务；
- 是否能发现“自动化不等于无人负责”；
- 是否知道哪些动作应保留人工审批；
- 是否会为低置信度、重复账号、数据缺失设计处理方式；
- 是否能用业务结果而不是模型调用次数衡量价值。

# 任务二：抖音爆款作品评论区机制拆解

## 任务说明

在抖音找到一个你认为有代表性的作品，分析它为什么能获得传播、互动或转化。要求进一步寻找 2—3 个可以参考的对象，例如同类作品、同一账号的其他作品、竞品内容或相似评论区，并通过评论区证据拆解作品背后的爆火机制。

这里的“爆火”不只指播放量高，也可以是评论质量高、用户强烈表达需求、讨论持续、产生咨询或形成明确购买意向。

## 输入条件

- 1 个公开抖音作品链接；
- 作品基本信息：账号、发布时间、标题 / 文案、时长、点赞 / 评论 / 收藏 / 分享等可见数据；
- 至少 2 个参考对象的链接；
- 至少 30 条评论样本，需覆盖高赞评论、普通评论、质疑评论、提问评论或转化意向评论中的至少 3 类；
- 允许使用 AI 做转写、聚类和归纳，但必须保留原始评论截图或链接证据。

## 期待输出

### A. 作品信息卡

| 字段 | 内容 |
|---|---|
| 作品链接 |  |
| 账号与内容类型 |  |
| 核心主题 / 用户问题 |  |
| 可见互动数据 |  |
| 目标受众 |  |
| 可能的业务目标 | 传播 / 涨粉 / 咨询 / 交易 / 其他 |

### B. 机制拆解

请至少分析以下 6 个环节：

1. 用户在前 3 秒被什么吸引；
2. 内容承诺了什么，是否快速兑现；
3. 哪个信息差、情绪点或冲突推动了观看；
4. 内容如何让用户产生评论、转发或收藏动机；
5. 评论区出现了哪些真实需求与反对意见；
6. 作品可能通过什么机制完成从注意到行动的转化。

每个判断都要标记为 **事实 / 推断 / 建议**。

### C. 评论区分析表

至少抽取并归类 30 条评论：

| 评论编号 | 评论原文 / 脱敏摘要 | 类型 | 用户需求或情绪 | 证据强度 | 对内容或业务的启发 |
|---|---|---|---|---|---|
| 01 |  | 提问 / 认同 / 质疑 / 求链接 / 购买意向 / 其他 |  | 高 / 中 / 低 |  |

### D. 参考对象对比

用表格回答：

| 对象 | 相似点 | 关键差异 | 可借鉴点 | 不应照搬的地方 |
|---|---|---|---|---|

### E. 可执行结论

最后输出：

- 这个作品最值得复用的 3 个机制；
- 一个可以在 7 天内验证的内容实验；
- 如果把它放进 Byering 的工作流，Agent 可以分别在哪些环节提供帮助；
- 你认为最容易被误判的地方是什么。

## 核心评判标准

| 评判维度 | 权重 | 好的表现 |
|---|---:|---|
| 证据完整性 | 25% | 链接、截图、评论样本和数据清楚，结论可回查 |
| 分析深度 | 25% | 能从表面“有趣”进一步解释用户动机和传播机制 |
| 评论区洞察 | 20% | 不只统计情绪，而是识别问题、需求、异议和意向信号 |
| 参考对象质量 | 15% | 对比对象有选择逻辑，能分辨可迁移与不可照搬 |
| 结构化表达与行动性 | 15% | 结论能转成具体内容实验或 Agent 任务 |

### 直接扣分项

- 把播放量高直接等同于内容有效；
- 用 AI 编造评论、数据、链接或账号信息；
- 只做“内容复述”，没有解释为什么；
- 把个别评论当成整体用户结论，且没有说明样本局限；
- 只给模糊建议，例如“加强互动”“提高质量”。

# 任务三：高意向用户识别与首触设计

## 任务说明

请从一个公开作品、评论区或模拟数据集中，识别最值得优先处理的潜在客户，并设计一套合适的首次触达方案。这个任务不要求发送真实私信，重点考察你能否基于有限证据做出谨慎、可解释、可执行的判断。

## 输入条件

二选一：

### 方案 A：公开数据

- 1 个公开抖音作品或账号；
- 20—50 条公开评论；
- 评论者可见的公开信息；
- 你选择的一个明确业务目标，例如售卖课程、预约咨询、到店服务或商品购买。

### 方案 B：模拟数据

自行创建 20 条评论和 5 个用户画像，但必须保证：

- 至少 5 条为明确高意向；
- 至少 5 条为低意向或无关；
- 至少 3 条为容易误判的边界案例；
- 不得使用真实个人隐私。

## 期待输出

### A. 线索评分表

| 用户 / 线索 ID | 关键证据 | 意向等级 | 分数 | 判断理由 | 仍需核验的信息 | 推荐动作 |
|---|---|---:|---:|---|---|---|

要求至少定义一套自己的评分规则，例如：

- 需求明确度；
- 时间紧迫度；
- 与产品的匹配度；
- 互动深度；
- 是否已经提出价格、链接、适用性或购买问题；
- 是否存在风险或勿扰信号。

### B. Top 3 Prospect Brief

对优先级最高的 3 个线索分别写：

- 公开可验证的信息；
- 可能的需求与触达切入点；
- 不能假设的内容；
- 首次触达目标；
- 如果对方不回复，下一步如何处理。

### C. 首触方案

为每个 Top 3 线索设计：

- 触达渠道；
- 首句；
- 具体话术，控制在 100 字以内；
- 需要人工确认的内容；
- 不能说的内容；
- 何种回复应转人工或停止触达。

### D. 风控说明

至少回答：

1. 哪些线索不能自动触达？
2. 哪些情况必须停止后续计划？
3. 如何避免重复触达、骚扰或错误承诺？
4. 如何记录证据、动作和结果，便于后续跟进？

## 核心评判标准

| 评判维度 | 权重 | 好的表现 |
|---|---:|---|
| 线索判断准确性 | 25% | 能区分明确意向、弱意向、无关和边界案例 |
| 证据与可解释性 | 20% | 每个分数都能回到具体评论或公开信号 |
| 触达个性化 | 20% | 话术回应真实问题，不套模板、不假装熟悉对方 |
| 风险意识 | 20% | 有勿扰、重复、权限、隐私、承诺和人工接管边界 |
| 执行完整度 | 15% | 结果可直接交给执行人员或 Agent 继续处理 |

### 直接扣分项

- 把“点赞 / 围观”直接判断为购买意向；
- 虚构用户身份、预算、职业、地区或购买能力；
- 未经授权设计自动发送或批量触达；
- 话术含有无法证明的承诺、夸大效果或虚假紧迫感；
- 没有停止条件和人工接管条件。

# 三、统一评分与筛选建议

## 1. 评分等级

| 等级 | 判断 |
|---|---|
| A：推荐进入复试 / 协作池 | 证据真实，问题定义清楚，分析有独立判断，方案可执行，能主动发现风险和下一步 |
| B：可培养 | 基础分析完整，但行业理解、证据意识或执行设计仍需辅导 |
| C：暂不推荐 | 主要依赖空泛观点，事实与推断混淆，缺乏可复现过程或忽略风险 |

## 2. 最重要的筛选信号

优先录用以下类型的候选人：

- 能把模糊任务拆成最小闭环；
- 会主动搜索证据，不满足于第一层答案；
- 能发现 AI 输出的问题并进行人工校验；
- 能从评论、行为和语境中判断真实意向，而不是只看表面互动量；
- 能把分析转成下一步动作、实验或 SOP；
- 知道不确定时应如何标记、补证和转人工；
- 表达清楚，结构稳定，交付物能被别人接着使用。

## 3. 不建议作为核心标准的指标

- 是否使用最复杂的模型；
- 是否写了大量代码；
- 文档是否做得特别长；
- 是否复述了 Byering 的产品术语；
- 是否给出了看起来“很宏大”的商业方案。

## 4. 面试追问建议

收到作品后，可任选以下问题追问：

1. 你最没有把握的一个结论是什么？如果再给你 2 小时，你会怎么验证？
2. 如果 AI 给出一个看似合理但没有证据的判断，你会怎样处理？
3. 哪一步你认为不能自动化？为什么？
4. 如果用户投诉被错误触达，你会如何定位问题并修改 SOP？
5. 如果只能保留一个 Agent，你会保留谁？为什么？

# 四、中介机构发布时可直接使用的简短说明

我们正在寻找对 AI、Agent、内容研究、增长运营和业务自动化感兴趣的学生。候选人不需要拥有完整的商业经验，也不要求写出完美产品，但需要能够围绕一个具体任务进行真实研究、使用 AI 辅助工作、提供可核验的证据，并把结论转化为可执行的流程或方案。

候选人可从 3 道题中任选 1 道完成；希望进一步展示能力的候选人可以提交第 1 题，或额外完成第 2、3 题。提交作品时请注明 AI 使用方式，并区分事实、推断和建议。

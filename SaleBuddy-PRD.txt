我暂用SaleBuddy来指代这款产品，对用户而言，SaleBuddy 是一个完整的个人助理。用户只需要向 SaleBuddy表达目标，SaleBuddy会理解需求、拆解任务、组织专业 Agent、分配工作、协调协作、处理异常，并最终向用户交付结果。

SaleBuddy 内部可以拥有多个子 Agent，例如线索猎人、数据分析师、销售顾问和开发助手。每个子 Agent 都拥有独立的岗位、能力、权限、记忆、工作空间和资源预算。并且每个子agent需要拟人化，赋予姓名、灵魂、性格，像一位真人。

整个产品可以理解为：
用户拥有一个 SaleBuddy，SaleBuddy 管理一支 AI 员工团队。
用户负责提出目标、制定规则和进行关键决策。SaleBuddy 负责组织和管理。子 Agent 负责具体执行。

当前多数 多 Agent 产品 要求用户直接管理多个 Agent。
用户需要自己判断：
1. 应该找哪个 Agent
2. 任务应该如何拆解
3. 哪些 Agent 需要参与
4. 谁负责统筹
5. 执行失败后应该找谁处理
6. 如何控制 Agent 的权限和成本
7. 如何查看不同 Agent 的工作过程

当 Agent 数量不断增加，用户会逐渐承担新的管理成本。
我们这款产品需要将这些复杂性收纳进一个统一的组织系统中。

用户只需要描述目标，例如：
帮我找到 200 个符合条件的潜在客户，并制定一套可执行的触达方案。
接下来由 SaleBuddy 完成内部组织：
1. 调用线索猎人寻找潜在客户
2. 调用数据分析师清洗和评估线索
3. 调用销售顾问制定触达策略
4. 调用内容策划生成沟通内容
5. 调用审核能力检查结果
6. 汇总并向用户交付最终方案
用户可以直接查看结果，也可以进入具体任务，了解每个 Agent 的工作过程。

核心产品理念是用户只需要面对一个主 Agent
SaleBuddy 是用户的统一交互入口。
用户无需频繁切换 Agent，也无需理解底层的任务编排逻辑。SaleBuddy会根据目标自动判断需要哪些能力，并组织合适的 Agent 完成任务。

在默认状态下，用户只与SaleBuddy 沟通。
在需要精细管理时，用户也可以进入具体 Agent 的个人页面，对其进行训练、调整和授权。


 子 Agent都 是 WorkBuddy 的员工
每个子 Agent 都是 SaleBuddy内部的一名专业员工。
用户可以理解每个 Agent 的岗位和能力，但日常管理主要由 SaleBuddy 负责。

Agent 可以被持续训练
当某个 Agent 的工作结果不符合预期时，用户可以直接对它进行反馈：
“以后寻找潜在客户时，优先筛选怎么怎么样的画像用户。”
“输出报告时，先给结论，再解释分析过程。”
“没有可靠来源的数据不要写入正式报告” 等等。
这些反馈可以被保存为 Agent 的长期规则，也可以设置为仅对当前任务或当前项目生效。
随着用户不断使用和调整，每个 Agent 会逐渐形成适合该用户的工作方式。


所以这款产品是三层组织结构。
第一层：用户
用户拥有最高控制权。
用户负责：
1. 提出目标
2. 制定预算
3. 设置权限
4. 审批高风险操作
5. 调整 Agent 的岗位和行为
6. 决定哪些规则需要长期保留

第二层：主Agent
WorkBuddy 是整个 AI 组织的负责人。
它类似于首席助理、幕僚长或 AI 公司管理者。
WorkBuddy 负责：
1. 理解用户目标
2. 拆解任务
3. 选择参与 Agent
4. 创建任务房间
5. 分配任务
6. 控制执行顺序
7. 协调 Agent 之间的合作
8. 处理异常和卡点
9. 审核交付质量
10. 向用户汇总结果

第三层：子 Agent
子 Agent 负责具体执行。
每个子 Agent 拥有明确的岗位职责、能力范围和权限边界，并对自己的工作结果负责。


每个Agent 都有一套统一的基本结构
1. Role：岗位职责
定义 Agent 的职业角色、工作范围和汇报关系。
例如：
你是一名 B2B 线索研究员，负责搜索、验证和整理潜在客户，并向 SaleBuddy 汇报结果。
2. Skills：核心能力
定义 Agent 能够完成哪些具体工作。
例如线索猎人的 Skills 包括：
1. 搜索潜在客户
2. 分析公司主页
3. 补全联系方式
4. 判断购买意向
5. 清洗重复数据
6. 对线索进行评分
Skill 可以被安装、移除、组合和升级。
3. Tools：工具
定义 Agent 可以使用哪些执行工具。
例如：
1. 浏览器
2. 搜索引擎
3. CRM
4. 邮箱
5. 数据库
6. Python
7. 第三方 API
8. 文件系统
Skill 代表 Agent 会做什么，Tools 代表 Agent 可以借助什么完成工作。
4. Scope：工作范围
定义 Agent 可以接触哪些数据和业务区域。
例如线索猎人可以访问公开互联网数据和指定的 CRM 线索库，但不能访问公司工资表、财务账户和核心代码仓库。
5. Permission：操作权限
定义 Agent 可以执行到什么程度。
例如：
1. 可以读取邮件
2. 可以创建邮件草稿
3. 发送邮件需要用户审批
4. 单次最多发送 20 封邮件
5. 不允许删除邮件
6. 不允许修改公司核心代码
6. Identity：对外身份
Identity 决定 Agent 对外展示的形象。
包括：
1. 名称
2. 头像
3. 职位
4. 语言风格
5. 对外签名
6. 沟通气质
7. 对外使用的身份信息
这些信息可以保存在 IDENTITY.md 中。
7. Soul：底层原则
Soul 是 Agent 相对稳定的行为内核。
包括：
1. 思考原则
2. 判断标准
3. 交付标准
4. 安全规则
5. 诚实原则
6. 用户授权原则
7. 群聊参与规则
8. 持续工作规则
Soul 决定 Agent 如何理解任务、如何做决策，以及什么情况下应该暂停执行。
8. Memory：记忆
每个 Agent 都拥有独立记忆。
记忆可以分为：
1. 用户记忆
2. 项目记忆
3. 岗位经验
4. 组织知识
5. 工作记录
6. 失败记录
7. 用户反馈
8. 已验证的最佳实践
记忆需要支持来源追踪、版本记录、删除、回退、有效期和权限控制，避免错误经验长期影响 Agent。
9. Workspace：工作空间--云电脑
每个 Agent 都拥有自己的工作空间，即云电脑。
其中包括：
1. 工作文件夹
2. 临时文件
3. 最终产出
4. 操作记录
5. 工具调用记录
6. 当前任务状态
7. 历史任务结果
用户可以像查看员工电脑一样，查看 Agent 当前正在处理什么。

Agent 遇到卡点时的处理机制
Agent 遇到问题后，应当先尝试自行解决。
推荐的处理顺序为：
1. 重新检查任务要求
2. 查询自己的记忆
3. 调用其他 Skills
4. 更换工具或执行方式
5. 请求专业 Agent 协助
6. 请求任务负责人协调
7. 请求 WorkBuddy 重新规划
8. 在确实需要用户判断时上报
当问题上报给用户时，应当同时说明：
1. 卡点是什么
2. 已经尝试了哪些方案
3. 失败原因是什么
4. 当前有哪些可选方案
5. 每个方案的成本和风险
6. 推荐用户选择哪一个
系统还需要设置最大尝试次数、最大消耗、最大协作深度和最大执行时间，防止 Agent 无限循环调用。


用户训练 Agent 的方式
用户对 Agent 的每次反馈Agent都需要主动向用户明确生效范围。
可以提供四种选择：
1. 仅本次任务生效
2. 当前项目生效
3. 对该 Agent 长期生效
4. 对整个 SaleBuddy 组织生效

例如用户说：
以后报告中所有数据都要附带来源。
系统需要询问用户希望这条规则只用于当前项目，还是成为整个组织的长期交付标准。
通过这种方式，可以减少临时反馈对长期行为造成的干扰。



产品的最终目的是帮助用户提高工作效率、产出

产品UE测体现的核心价值是
1. 降低多 Agent 使用门槛
用户只需要面对 SaleBuddy，不需要学习复杂的 Agent 调度方法。
2. 建立长期个性化能力
每个 Agent 都会在长期使用中积累记忆、经验和用户偏好。
3. 提供真实执行能力
Agent 可以调用浏览器、邮箱、CRM、代码环境和业务系统，完成实际任务。
4. 提供组织级管理能力
用户可以管理员工、团队、任务、权限、文件和预算。
5. 提供透明的执行过程
用户能够看到 Agent 在做什么、为什么这样做、消耗了多少资源，以及最终产生了什么结果。
6. 建立用户的拥有感
用户获得的是一支长期属于自己的 AI 团队。
随着使用时间增加，这支团队会逐渐了解用户的业务、偏好、规则和工作方式。


SaleBuddy 的特点可以概括为四点。
1. 单一主 Agent 入口
用户只需要管理一个SaleBuddy，内部 Agent 调度由系统完成。
2. 完整的 Agent 员工模型
每个 Agent 都拥有岗位、能力、身份、原则、权限、记忆、工作空间和预算。
3. AI 组织可视化
通过好友栏、任务房间、办公室和电脑桌面，将抽象的 Agent 执行过程转化为用户可以理解的组织结构。
4. 成本与权限可控
每个 Agent 的工具、数据、操作权限和资源预算都可以单独管理。

一句话定位
SaleBuddy 是用户的 AI 幕僚长。用户只需要表达目标，SaleBuddy 会组织和管理一支专业 AI 员工团队，控制任务、权限、记忆、成本和执行过程，并向用户交付最终结果。

愿景
未来，每个人都可以拥有一支长期服务于自己的 AI 团队。
这些 AI 员工了解用户的目标、偏好、业务、规则和工作方式。它们可以持续学习、相互协作、调用工具并完成真实任务，带来真实的产出。
SaleBuddy 希望成为人与 AI 员工组织之间的统一入口，让一个人也能拥有过去只有公司才能具备的组织能力。

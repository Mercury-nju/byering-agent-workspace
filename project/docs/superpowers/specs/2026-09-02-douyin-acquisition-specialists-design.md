# 抖音获客专家设计

**日期：** 2026-09-02  
**状态：** 已确认设计，待规格审查与实现计划  
**范围：** Agent 广场、成员私信、实时工作、成果中心、抖音能力编排

## 1. 背景与目标

当前产品已经有四类可单独使用的抖音 Agent：

- 作品评论潜客筛选专员：一次性读取和筛选评论中的潜客；
- 作品评论筛选专员：按指定条件筛选评论，不判断购买意向；
- 私信触达专员：执行用户确认后的主动私信；
- 私信承接 / 自动回复专员：监听已授权账号私信并生成或发送承接回复。

这些 Agent 的边界需要保持不变。新增能力的目标不是创建一个可见的“获客父 Agent”，而是增加两个平级、可独立雇佣、可长期运行的专家：

1. **评论区获客管家**：围绕作品评论发现潜客，并按确认策略持续触达；
2. **直播间获客专家**：围绕直播间互动发现潜客，并按确认策略持续触达。

“获客”是 Agent 广场的能力分类和产品语义，不是另一层 Agent hierarchy。

## 2. 设计原则

### 2.1 一个 Agent 就是一个专家

两个新专家各自拥有独立的：

- Agent 身份和成员卡片；
- 雇佣合同；
- 抖音授权状态；
- 专属云电脑和浏览器会话；
- 长期任务；
- 私信对话、实时工作状态和成果记录。

内部可以复用评论采集、意向分析、风控和私信发送等共享服务，但这些服务不作为用户可见的子 Agent。

### 2.2 任务持续运行，云电脑健康与任务健康分离

获客专家确认后默认进入长期运行状态，直到用户暂停或关闭。云电脑启动慢、页面暂时无画面或单次读取超时，不应直接终止长期任务。

系统分别维护：

- 云电脑状态：`provisioning`、`online`、`connecting`、`disconnected`、`recovering`；
- 任务状态：`configuring`、`running`、`paused`、`degraded`、`error`、`stopped`。

只有健康检查确认云电脑掉线、授权失效或执行接口明确失败时，任务才进入异常；网络读取超时优先重试、查询幂等结果或进入降级队列。

### 2.3 真实能力优先

界面只开放已被实际接口验证的执行通道。当前可作为第一期真实闭环的能力是：

- 公开作品与评论读取；
- 评论意向/条件分析；
- 已授权账号私信发送；
- 发送结果记录和长期监听。

评论区公开回复、直播互动读取或直播触达必须经过对应 MCP/RPA 能力探测与成功回执验证；未验证时显示为不可执行，并提供私信触达或人工处理路径，不能用 mock 结果冒充已完成。

## 3. Agent 定义

### 3.1 评论区获客管家

**使命：** 从指定抖音作品评论中找到符合目标的人，基于评论证据生成并执行合适的触达，持续沉淀有效回复。

**配置流程：**

1. 用户雇佣专家；
2. 选择或新增抖音授权账号；
3. 选择评论来源：自己的作品或指定他人的作品；
4. 选择作品范围、时间窗口和抓取频率；
5. 定义目标人群和意向信号，例如价格、求链接、适配性、购买时间、竞品比较；
6. 选择触达方式：私信；评论区公开回复只在能力探测通过后可选；
7. 配置触达内容策略，而不是只保存一段孤立文本：
   - 是否引用评论原话；
   - 首触语气和长度；
   - 缺少上下文时的处理；
   - 涉及价格、承诺、投诉时的转人工规则；
   - 每日上限、账号冷却和停止条件；
8. 展示执行预览，用户确认后启动长期任务。

**持续循环：**

```text
读取评论 → 标准化与去重 → 意向/条件判断 → 风控
→ 生成触达草稿 → 按审批规则发送 → 查询回执
→ 监听回复 → 更新线索与成果 → 进入下一轮
```

### 3.2 直播间获客专家

**使命：** 从指定直播间的真实互动中识别潜客，并根据互动上下文持续完成触达与回流。

**配置维度：**

- 自己的直播间或指定他人的直播间；
- 直播场次、时间窗口和监听频率；
- 弹幕、评论、提问、商品点击等已被接口支持的信号；
- 目标人群、意向判断规则和触达方式；
- 触达内容、频控、冷却和停止条件。

直播专家复用与评论专家相同的任务状态、审计和成果模型，但来源证据必须包含直播场次、发生时间和互动原文。

第一阶段的产品承诺必须与真实接口能力一致：直播间互动读取和触达能力通过探测后，直播间获客专家才进入“可雇佣、可启动”状态。在探测通过前，市场仍可展示该专家的定位和能力说明，但明确标记为“能力准备中”，不可创建长期任务，也不展示模拟产出。探测通过后，才开放与评论区专家一致的配置、审批、执行和成果链路。

## 4. 共享服务与可见边界

### 4.1 共享服务

以下是平台级服务，不是 Agent：

- 抖音账号授权与状态探测；
- 每 Agent 独立云电脑注册、恢复和心跳；
- 公开数据读取适配器；
- 意向/条件分析器；
- 去重、冷却和风险检查；
- 触达执行适配器；
- 长期任务调度与幂等重试；
- 活动日志、成果记录和事件回放。

### 4.2 用户可见边界

用户只看到“评论区获客管家”或“直播间获客专家”的工作，不需要理解内部调用了哪些共享服务。内部事件统一挂在该专家的 `agentId`、`taskId` 和 `accountId` 下，避免出现“任务完成但不知道是谁完成”的问题。

### 4.3 触达审批模式与状态机

触达内容不是配置完成后就默认发送，必须先明确审批模式。第一阶段提供三种模式：

- `manual`：逐条人工确认，默认模式。Agent 只能生成草稿并进入待确认，不得越过确认直接发送；
- `batch`：按本轮候选批量确认。用户确认批次、数量和内容模板后，批次内逐条执行并记录回执；
- `auto`：用户明确开启后自动发送，仅允许低风险内容，并受每日上限、发送间隔、冷却时间和平台限制约束。

价格、优惠、投诉、退款、合同、效果承诺和无法从业务知识确认的事实，无论采用哪种模式都必须转人工，不能进入自动发送。

触达状态统一为：

```text
draft → pending_approval → approved → submitted
pending_approval → rejected
submitted → accepted → delivered
submitted → unknown → delivery_checking → delivered / failed
submitted → failed → retry_queued / stopped
```

在 `manual` 或 `batch` 模式下，长期任务仍可继续扫描、分析和生成草稿，但发送队列停在 `pending_approval`；只有 `auto` 模式且通过风控的草稿才能自动进入 `approved`。所有状态变化必须同步到成员私信、实时工作和成果中心。

## 5. 数据流与页面联动

### 5.1 成员私信

每个关键事件都写入对应专家的私信对话：

- 授权请求、授权完成或授权失败；
- 云电脑启动、连接、恢复和掉线；
- 本轮扫描范围和新增候选数；
- 意向判断和风控结论；
- 触达草稿、待确认项和发送回执；
- 回复回流、暂停原因和异常通知；
- 长期任务的每日/每轮摘要。

用户离开配置页后，任务继续运行；回到成员页点击专家对话即可继续操作。

### 5.2 实时工作

实时工作只展示该专家当前真实运行的任务，至少包含：

- 云电脑实时画面或明确的连接/恢复状态；
- 当前阶段、阶段进度和最近真实事件；
- 当前账号、任务规模和最近一次回执；
- 异常原因、自动恢复次数和人工操作入口；
- 暂停、恢复、关闭长期任务。

进度只允许来自实际采集、分析、发送或回执事件；没有真实进度时显示“等待服务回执”，不使用静态百分比。

### 5.3 成果中心

评论区专家至少产出：

- 候选潜客清单；
- 评论原话、作品链接、时间和判断依据；
- 触达记录、平台回执和失败原因；
- 回复会话和下一步建议；
- 长期运行摘要。

直播间专家至少产出：

- 直播场次和互动证据；
- 观众意向分层；
- 触达与回复记录；
- 运行摘要和异常记录。

成果按 `agentId + taskId` 归属，支持从成果反查成员对话和实时任务。

## 6. 错误处理与恢复

### 6.1 可恢复错误

- 云电脑仍在连接：保持任务为 `running` 或 `degraded`，继续心跳，不立即失败；
- 单次读取超时：使用稳定 `reqId` 重试，避免重复发送；
- 页面打开失败：重新连接或进入人工授权/人工操作入口；
- 回执暂缺：标记 `unknown`，查询成功/失败后再收口。

### 6.2 需要用户介入的错误

- 授权失效或账号被登出；
- 云电脑持续掉线且自动恢复失败；
- 平台明确拒绝触达；
- 触达策略缺少必要信息；
- 命中价格、退款、投诉、承诺等转人工边界。

所有错误都要同时出现在实时工作和成员私信中，并保留原始错误、发生时间、重试次数和建议动作。

## 7. 第一阶段范围

### 包含

- 新增两个平级 Agent 的市场定义、档案和雇佣入口；
- 评论区获客管家的真实长期任务闭环：评论读取、分析、去重、风控、私信触达、回执和成果；
- 独立云电脑和授权状态复用现有持久化机制；
- 成员私信、实时工作和成果中心的事件联动；
- 失败重试、掉线恢复、暂停和关闭；
- 真实能力探测和不可用通道的阻断提示。

### 不包含

- 创建可见的父级“获客 Agent”；
- 修改现有四个 Agent 的单独使用逻辑；
- 直播互动读取/触达能力未通过真实接口探测前，不开放直播间获客专家的雇佣和长期任务；
- 在没有真实接口支持时开放直播互动或评论公开回复；
- 用静态演示数据伪造长期任务产出；
- 与本次目标无关的办公室视觉重构。

## 8. 验收标准

1. 市场中能看到两个平级专家，不出现父级获客卡片；评论区获客管家在第一阶段可雇佣，直播间获客专家在能力探测通过前明确显示“能力准备中”且不可雇佣或启动；
2. 评论区专家完成授权后，关闭配置页，任务仍继续运行；
3. 新事件能在成员私信、实时工作和成果中心按同一 `taskId` 对上；
4. 云电脑启动慢不会被短超时误判为任务失败；
5. 云电脑真实掉线时能显示异常、尝试恢复并保留任务记录；
6. 评论筛选和私信发送均使用真实接口回执，失败时不生成“已发送”；
7. 用户可以暂停、恢复和关闭长期任务；
8. 已有四个 Agent 仍可独立雇佣和使用，互不改写任务边界；
9. 能力未验证的通道不可点击执行，并有清晰替代路径；
10. `manual`、`batch`、`auto` 三种审批模式的状态流转、风控拦截和回执均可审计；
11. 测试覆盖正常运行、重复事件、超时重试、掉线恢复、授权失效、审批状态和成果归属。

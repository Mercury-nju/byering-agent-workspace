## 一、背景

### 1. 概述

Byering 2C 端面向 **Pro-C 与 Solo Business（小 B）**，是一个针对抖音平台的智能获客与触达 Agent。

产品通过一个主 Agent 与多个专业 Agent 协作，帮助用户持续完成完整的业务链路：

```text
发现潜在客户
    → 判断客户价值
    → 研究客户
    → 制定触达策略
    → 执行触达
    → 持续跟进
    → 沉淀客户与业务资产
```

Byering 的核心不是让用户学习如何使用一组 Agent，而是把复杂的 Agent 组织、任务编排、工具调用和异常处理收进产品内部。用户无需手动配置大量工作流，也无需先理解每个 Agent 的技术能力，就可以让账号营销、运营、获客和持续转化自动运行。

用户可以用两种方式开始工作：

1. **主动式入口**：Agent 没有任务时主动告诉用户“我可以做什么”“我建议你现在做什么”，直接提供可执行选项；用户选择后即可执行。
2. **自然语言入口**：用户直接描述目标，主 Agent 自动理解需求、创建项目、组织 Agent 团队并推进任务。

所有 Agent 都应表现出积极主动的 E 型人格：有任务时主动汇报，遇到风险时及时提醒，没有任务时主动提出下一步建议。自然语言是补充入口，不是用户必须学习的唯一操作方式。

例如用户说：

> 帮我找到最近 7 天对某款商品表现出明确购买意图的消费者，筛选高意向用户并完成触达。

主 Agent 会自动完成目标理解、任务拆解、人员搜索、线索分析、客户研究、触达策略制定和执行，并持续向用户汇报过程与结果。涉及外部发送、账号权限或平台限制时，系统会在具体动作层面请求确认，不会用模糊授权代替人工判断。

### 2. 一句话定位

> **面向 Pro-C 与 Solo Business 的抖音智能获客与触达 Agent，通过多 Agent 协作持续发现高价值潜客、自动完成触达，并沉淀业务记忆与客户资产。**

### 3. 典型使用场景

#### 场景 A：从公开内容中主动找人

用户给出商品、账号、作品或目标人群。Byering 读取授权范围内的公开视频、评论、互动和行为信号，识别表达价格、求链接、适配性、购买时间、竞品比较等明确意向的用户，形成可回查的潜客清单。

#### 场景 B：经营者每天的主动获客

每天开始工作时，Byering 主动汇报：今日新增高意向用户、值得再次跟进的老客户、待处理回复、异常账号和推荐动作。用户可以直接选择“先联系高意向用户”“继续研究竞品评论区”“召回 30 天未复购客户”等选项。

#### 场景 C：从发现到触达的连续推进

Byering 不把找线索、写话术、发消息拆成几个孤立工具。它会把线索发现、意向判断、客户研究、触达策略、审批、发送、回复和后续跟进串成一个持续任务。

#### 场景 D：一个人就是一个业务团队

个体卖家、主播、内容创作者、专业顾问和小型商家可以拥有一支长期工作的数字员工团队，把重复的研究、筛选、记录和跟进交给 Agent，自己集中精力在产品、内容、品牌和最终决策上。

## 二、与 AI 数班的关系

### 1. 联系：同一条业务链路，同一套产品底座

Byering 与 AI 数班使用一套统一的获客与触达 Agent 产品底座。Pro-C 是默认产品体验，同时也可以通过切换企业空间，承载汽车、医美、房地产等 B 端企业级业务。

二者本质上都在解决同一条业务链路：

```text
发现客户 → 判断意图 → 研究客户 → 触达 → 跟进 → 转化
```

共用的底层能力包括：主 Agent 编排、专业 Agent、Skill、Automation、Memory、任务运行、权限、审批、预算、证据、连接器和业务资产沉淀。

### 2. 区别：个人经营与组织经营

| 维度 | Pro-C / Solo Business | AI 数班 / 企业空间 |
|---|---|---|
| 核心用户 | 一个专业能力者或一个小型业务 | 汽车门店、医美机构、房地产公司等组织 |
| 经营状态 | 一个用户往往就是一个业务单元 | 一批销售、一批账号、一套 SOP 和一套客户数据 |
| 核心问题 | 已有商品、内容、账号或流量，但缺少稳定主动获客能力 | 如何规模化执行获客、触达和跟进，并统一管理结果 |
| 重点价值 | 让一个人拥有可持续工作的 AI 业务团队 | 让组织把获客能力复制到人员、账号和项目 |
| 典型体验 | Agent 主动推荐任务，用户选择后直接执行 | 管理团队、账号、权限、SOP、审批和绩效 |

Pro-C 用户通常已经具备专业能力、内容能力或一定流量，缺少的是稳定、持续、高效率的主动获客能力。企业用户则更关心规模化、标准化、可管理和可审计。

### 3. 产品承载方式：统一账户，两种 Workspace

账户体系保持统一，Workspace 分为两类：

- **个人空间**：面向 Pro-C 与 Solo Business，强调快速启动、主动建议、少配置和个人资产沉淀；
- **企业空间**：面向汽车、医美、房地产等企业业务，强调组织成员、销售团队、账号、SOP、审批、权限和绩效管理。

两类 Workspace 复用核心业务对象和底层执行能力，包括潜客、客户、任务、触达动作、回复、文件、记忆和证据，同时允许前端页面结构、导航和管理深度明显不同。

## 三、产品价值与商业潜力

### 1. 用户痛点洞察

大量 Pro-C 经营者已经拥有商品、内容、账号和一定流量，但缺少一套能够持续主动发现客户并完成触达的能力。

以抖音电商经营者为例，一个个体卖家每天可能面对大量潜在消费者信号：

- 用户在商品视频下询问价格；
- 用户评论“求链接”；
- 用户询问产品是否适合自己；
- 用户在竞品评论区表达购买需求；
- 用户进入直播间并多次互动；
- 用户关注账号但迟迟没有购买；
- 老客户长时间没有复购；
- 用户浏览和互动了大量同类商品内容。

这些信号已经存在于平台中，但绝大部分没有被进一步利用。一个个人经营者很难每天手动完成：

```text
发现 → 筛选 → 研究 → 判断 → 触达 → 跟进 → 记录
```

当潜在消费者数量增加后，问题会更加明显。用户真正想知道的是：

- 今天谁最值得我主动联系？
- 哪些人已经表现出了购买意图？
- 我的粉丝和互动用户里面，谁最可能购买？
- 哪些已经接触过的人值得再次跟进？
- 哪些重复工作可以直接交给 Agent？

Byering 的产品需求，就来源于这些真实、持续、高频的经营行为。

### 2. 产品价值

Byering 让 Pro-C 用户第一次拥有一支针对获客与触达场景、可以持续工作的 AI 业务团队，把过去只有较成熟企业才能拥有的获客、客户研究、销售运营和自动化能力，下沉到个人经营者。

产品由以下能力共同组成：

```text
一个主 Agent + 多个专业 Agent + Skills + Automation + Memory
```

它帮助个人经营者：

- 持续发现高价值潜客；
- 判断客户意图和优先级；
- 研究客户背景与行为证据；
- 生成并执行合适的触达动作；
- 持续跟进回复和未转化客户；
- 把客户、线索、话术、结果和经验沉淀为业务资产；
- 把时间从重复劳动中释放出来，投入产品、内容、品牌和最终决策。

产品价值必须尽量直接对应用户的经营结果。用户无需理解复杂的 Agent 架构，只需要看到：

- 今天多发现了多少潜客；
- 多联系了多少高意向消费者；
- 获得了多少回复；
- 产生了多少有效咨询；
- 增加了多少交易机会；
- 沉淀了多少可复用的客户和业务资产。

只要这些数字持续产生增量，产品价值就可以直接对应到用户收入。

### 3. 商业潜力

抖音电商拥有规模庞大的个体经营者、达人电商、小型商家、主播、内容创作者和一人经营团队。根据 2025 年 9 月抖音创作者大会披露的年度数据，在此前一年中：

- 超过 536 万新商家通过抖音电商获得收入；
- 超过 511 万新电商创作者通过抖音电商获得收入。

这说明中小商家、中小达人和个人创作者仍然是抖音电商生态的重要增长力量。对 Byering 而言，核心商业判断可以概括为：**用户池足够大，且用户需求紧贴交易环节。**

正式对外材料引用上述数据时，应补充大会原始来源与统计口径。

### 4. 商业化空间

Byering 服务的是非常接近交易环节的业务流程，商业价值可以围绕业务结果和执行资源同时建立：

- 有效潜客数量；
- 高意向潜客数量；
- 触达人数；
- 回复率；
- 有效咨询数量；
- 留资数量；
- 复购召回数量；
- 最终成交数量。

未来商业模式可以包括：

- 订阅收费；
- 按额度或执行量计费；
- 按 Workspace、账号、团队或结构收费；
- 高级连接器、云电脑和数据能力收费；
- 企业版的权限、审批、审计和绩效管理收费。

具体价格、计费单位和结果分成方案待后续验证。

### 5. 战略价值

Byering 不只是一个 2C 获客工具，也是一套可以同时承载 Pro-C 与传统 B 端业务的统一 Agent 产品底座。

汽车、医美、房地产等 B 端业务已经验证了一系列真实需求，而这些能力与 Pro-C 场景在底层高度共通：客户发现、意图判断、客户研究、触达、跟进、审批、记录和转化。

因此产品具备自然扩展路径：

```text
Pro-C → Solo Business → Team → Enterprise
```

## 四、产品工作方式

### 1. 主 Agent：用户唯一的业务入口

主 Agent 是用户的 AI 幕僚长，负责把用户的经营目标转成持续执行的业务任务。用户默认不需要选择具体 Agent，也不需要理解任务图、工具链或底层调度逻辑。

主 Agent 负责：

- 理解目标、范围和约束；
- 创建项目和任务；
- 搜索并组织合适的专业 Agent；
- 分配工作、安排顺序和控制依赖；
- 监控执行、风险、预算和审批；
- 根据新信号调整计划；
- 持续向用户汇报过程和结果；
- 沉淀客户与业务资产。

### 2. 主动式 Agent 交互

Byering 不应等待用户每次写出完整 Prompt。主动式 Agent 的交互规则是：

- 有任务：主动汇报“已经完成什么、正在做什么、下一步是什么”；
- 遇到卡点：主动说明问题、可选方案、成本风险和推荐项；
- 没有任务：主动总结“我发现了什么机会”，并推荐用户下一步可以做什么；
- 需要用户判断：直接给出少量明确选项，减少开放式配置；
- 用户想精细控制：允许通过自然语言或详情页调整目标、规则、权限和范围。

主动推荐必须基于真实信号、授权范围和当前业务上下文，不为了制造活跃感而虚构机会。

### 3. 多 Agent 协作

典型的销售获客任务由以下岗位协作完成：

| 岗位 | 职责 |
|---|---|
| 获客策略师 | 定义人群、渠道、筛选条件和获客节奏 |
| 线索挖掘员 | 发现账号、作品、评论和候选潜客 |
| 线索分析师 | 清洗、去重、评分和判断优先级 |
| 客户研究员 | 研究公开资料、行为证据和客户背景 |
| 销售顾问 | 制定触达角度、话术、CTA 和跟进策略 |
| 风控专员 | 检查账号、授权、DNC、频控、重复和风险 |
| 外联专员 | 执行已批准的外部触达动作 |
| 触达运营专员 | 管理排队、重试、送达、回复和人工交接 |

幕僚长负责统一组织和交付。专业 Agent 只执行自己岗位范围内的工作，不能自行扩大权限或创建不受控的子 Agent。

### 4. 业务任务的完整链路

```text
用户目标
  ↓
目标理解与必要澄清
  ↓
创建项目 / 任务 / 目标人群
  ↓
组织 Agent 团队
  ↓
发现潜客与采集公开信号
  ↓
身份确认、去重、意向判断与客户研究
  ↓
生成触达策略与草稿
  ↓
风控检查、授权与人工审批
  ↓
执行触达、检查送达与接收回复
  ↓
持续跟进、人工接管与转化
  ↓
沉淀客户资产、业务记忆与复盘结果
```

## 五、核心产品模块

### 1. 主对话工作台

用户可以在主对话中提出目标，也可以直接选择 Agent 推荐的经营动作。工作台按业务阶段展示：

- 今日机会与推荐动作；
- 目标理解与待确认信息；
- 执行计划和参与 Agent；
- 潜客发现、分析和研究进展；
- 触达草稿与审批项；
- 回复、跟进和人工接管；
- 最终结果、文件、证据和下一步。

### 2. 项目与任务

自然语言目标可以自动创建项目。项目承载目标人群、账号、任务、客户、文件、记忆、预算和结果，避免每次从零开始。

任务可以持续运行、暂停、恢复、重试、取消和重规划。任务完成不等于客户关系结束，后续回复、跟进和复购仍然可以继续进入同一个客户资产体系。

### 3. 团队与 Agent 广场

用户可以查看自己的数字员工、岗位、状态、当前任务、能力和推荐用途。Agent 广场用于发现和配置适合不同业务目标的专业能力，但不要求用户在每次任务前手动组队。

### 4. Agent 详情页

详情页用于在需要精细管理时查看和调整员工：

- Identity：名称、头像、职位和沟通风格；
- Soul：稳定的判断原则、交付标准和安全边界；
- Role：岗位职责和汇报关系；
- Skills：可安装、移除和组合的能力；
- Tools：可调用的浏览器、平台、CRM、文件和 API；
- Scope：可访问的账号、项目、客户和数据；
- Permission：读取、起草、发送、修改和禁止操作；
- Memory：用户偏好、项目规则、岗位经验和失败记录；
- Workspace：文件、临时环境、操作记录和历史产出；
- Budget：日、月、单任务预算和调用上限。

### 5. 任务房间

任务房间是一次具体业务工作的协作空间，明确目标、负责人、参与 Agent、截止时间、预算、工具、数据权限、交付物、验收标准和最大尝试次数。

房间内允许 Agent 协作、交换文件和汇报，但正式交接以结构化产物、证据和工作结果为准，不把自由聊天当成业务事实。

### 6. 客户与线索中心

线索中心围绕客户生命周期管理：候选、已确认、高意向、待触达、已触达、已回复、人工接管、已转化、拒绝、DNC 和未知。

每条线索应保留来源、采集时间、意向信号、评分依据、触达历史、回复、风险和下一步。昵称不作为唯一身份，缺失信息不强行补齐。

### 7. 触达中心

触达中心集中管理触达计划、话术版本、发送对象、审批状态、发送结果、送达状态、回复和跟进计划。平台能力或账号授权不足时，清楚显示阻断原因，并提供人工发送或只读研究路径。

### 8. AI 办公室

AI 办公室让用户看到数字员工正在做什么：空闲、规划、执行、浏览网页、分析数据、编写文件、协作、等待审批、遇到阻塞或完成任务。

办公室的主要价值是情感体验与执行可观测性。现有办公室场景、地图、角色、动画和状态机属于稳定体验边界，外围产品只读取同一份任务事实进行联动，不另建状态源，也不通过重做视觉来掩盖执行事实。

### 9. 文件、资源与知识库

- **文件中心**：管理用户文件、Agent 私有文件、项目共享文件、最终交付文件和临时执行文件；
- **资源中心**：查看模型 Token、API、云电脑、存储、数据采购和任务成本，并比较投入产出；
- **知识库**：沉淀组织规则、业务资料、客户研究、已验证话术和可复用经验。

## 六、Agent 记忆、自动化与用户训练

Byering 的长期价值来自持续积累，而不是一次性完成任务。系统需要同时管理三类资产：

1. **客户资产**：客户身份、来源、意向、沟通、回复、转化和关系状态；
2. **业务资产**：项目、话术、筛选规则、素材、报告、SOP 和结果；
3. **组织记忆**：用户偏好、岗位经验、失败记录和已经验证的最佳实践。

用户反馈可以直接作用于 Agent，例如：

- “以后筛选潜客时，优先看预算和明确购买时间。”
- “报告先给结论，再解释依据。”
- “没有可靠来源的数据不要写进正式报告。”

系统必须确认反馈的生效范围：

1. 仅本次任务；
2. 当前项目；
3. 对该 Agent 长期生效；
4. 对整个组织生效。

Automation 用于执行可重复的周期任务，例如每日发现新潜客、每周复查未回复客户、定期召回沉默客户。自动化仍然必须遵守当前权限、预算、频控、审批和平台能力边界。

## 七、权限、审批与可信执行

### 1. 权限边界

每次执行都需要同时检查数据范围、账号授权、操作类型、资源上限和审批策略。Agent 具备某项 Skill，不代表它可以访问所有数据或执行对应外部动作。

### 2. 外部触达原则

- 只使用已授权数据和明确公开来源；
- 不登录或读取未授权的私域信息；
- 不自动发送未经批准的外部消息；
- 不把网络异常当成发送成功；
- 不因为重试而重复触达同一对象；
- 官方平台能力不可用时，不使用 Demo 数据或绕过平台限制伪装成功。

### 3. 证据与结果

正式结果必须能回到来源、工具回执、文件或可复现的验证记录。没有可靠依据的结论标记为待核验或未知。

### 4. 卡点升级

Agent 遇到问题时按以下顺序处理：

```text
重新检查要求
  → 查询记忆
  → 更换 Skill
  → 更换工具或执行方式
  → 请求专业 Agent 协助
  → 请求负责人协调
  → 请求幕僚长重规划
  → 在确实需要用户判断时上报
```

上报必须说明卡点、已尝试方案、失败原因、可选方案、成本风险和推荐项。系统同时设置最大尝试次数、最大消耗、最大协作深度和最大执行时间，防止 Agent 无限循环。

## 八、产品阶段

### MVP：验证“主动获客到触达转化”的闭环

- Pro-C 个人空间与统一账户；
- Byering 主 Agent 主动建议与自然语言入口；
- 项目、任务和目标人群创建；
- 抖音公开内容、评论和互动信号的线索发现；
- 线索清洗、去重、意向判断和客户研究；
- 触达策略、草稿、风控检查和人工审批；
- 触达执行、回复接收、持续跟进和人工接管；
- 团队列表、Agent 详情页与任务房间；
- 客户与线索中心、文件中心和执行记录；
- 业务记忆、四档反馈训练和基础自动化；
- AI 办公室状态联动。

### 第二阶段：形成可经营的 AI 业务团队

- 更完整的主动推荐和每日经营简报；
- Agent 云电脑与工作桌面；
- 账号级工作区和更多抖音连接器能力；
- 自动团队组建与任务模板；

### 第三阶段：从个人业务到企业组织

- Team 与 Enterprise 的多用户协作；
- 汽车、医美、房地产等行业化 Workspace；

- 跨项目客户资产与组织级经营分析；
- 更复杂的长期自动化和受控自治协作。

## 九、商业化与指标

### 1. 核心商业指标

- 新增有效潜客数量；
- 高意向潜客数量；
- 触达人数与回复率；
- 有效咨询、留资和复购召回数量；
- 交易机会与最终成交数量；
- 每个任务、账号和 Workspace 的获客成本；
- 用户节省的人工时间与减少的返工次数。

### 2. 产品健康指标

- 从目标输入到首个有效潜客的时间；
- 主动推荐被采纳的比例；
- 任务完成率、重规划率和人工接管率；
- 证据覆盖率和待核验数据比例；
- 触达重复拦截率、审批通过率和异常恢复率；
- 用户连续使用天数、持续运行的自动化数量和客户资产复用率。

### 3. 商业化验证顺序

第一步验证用户是否愿意为“持续产生有效潜客和触达机会”付费；第二步验证不同用户对额度、账号、Workspace、云电脑和企业管理能力的付费边界；第三步再探索订阅、额度、结构和结果相关的组合收费。

## 十、产品边界与设计判断

Byering 的重点是帮助用户持续经营，而不是展示 Agent 数量或制造复杂的自动化配置。以下内容不属于第一阶段承诺：

- 让用户手动管理一组相互独立的 Agent；
- 无限递归的 Agent 自治或无主持人群聊；
- 自动批准高风险外部动作；
- 在平台不支持或未授权时绕过限制触达；
- 将所有执行内容自动写入永久记忆；
- 用模拟数据冒充真实潜客、发送、回复或成交结果；
- 用重做 AI 办公室替代真实任务状态、证据和业务结果。

## 十一、最终愿景

每个 Pro-C 和 Solo Business 都可以拥有一支真正长期工作的 AI 获客与触达团队。

这支团队了解用户的商品、内容、账号、客户、偏好、规则和经营节奏，能够主动发现机会、判断意向、研究客户、完成触达、持续跟进，并把每次经营结果沉淀成下一次更有效的业务资产。

随着 Workspace 从个人空间扩展到 Team 与 Enterprise，Byering 也将成为汽车、医美、房地产等行业统一的 Agent 业务底座。

> **Byering 不是替用户聊天，而是替用户持续找客户、联系客户、跟进客户，并把结果沉淀为可增长的业务资产。**

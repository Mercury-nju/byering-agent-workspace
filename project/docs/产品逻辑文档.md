# Byering Agent 产品逻辑文档

**版本：** 当前实现版
**最后核对：** 2026-09-14
**适用对象：** 产品、设计、研发、运营、销售、客户成功与测试

> 本文描述当前代码已经实现的产品逻辑、状态口径和能力边界。历史材料中“幕僚长自动拆解目标、自动派发任务、自动调度多个 Agent”的表述，不代表当前实现；如有冲突，以本文为准。

---

## 1. 产品定义

Byering 是面向抖音经营场景的 Agent 工作台。产品的目标不是提供泛用聊天，而是将抖音中的互动用户沉淀为可验证、可持续推进的业务资产。

```text
发现互动用户
  -> 保留来源证据
  -> 分析是否值得推进
  -> 完成首次私信触达
  -> 持续承接对话
  -> 留资、成交跟进与成果沉淀
```

### 1.1 产品原则

1. **真实结果优先。** 未经来源证据、平台回执或持久化记录确认的内容，不能展示为已完成。
2. **账号边界优先。** 监听、首次私信和私信承接都必须基于用户已授权的抖音账号。
3. **对话与执行分开。** 对话用于咨询、解释、结果同步和入口引导；外部动作必须通过对应 Agent 的结构化流程完成。
4. **业务状态可回查。** 每个潜客、触达和留资结果都应可追溯到来源账号、任务、原始表达和时间。
5. **下游只使用上游真实结果。** 找人、分析、首次触达和承接通过结构化结果交接，不补造上下文。
6. **失败不伪装。** 授权失效、平台异常、发送未知或数据不足，要明确展示阻塞、失败或等待回执。

### 1.2 核心对象

| 对象 | 定义 | 核心约束 |
| --- | --- | --- |
| 授权账号 | 用户连接并允许使用的抖音账号 | 账号级读取、私信发送和承接只能在该账号内发生 |
| Agent | 职责边界明确的业务能力单元 | 不跨越自身职责自行执行其他能力 |
| 任务 | 一次可运行、可追踪的执行单元 | 有独立状态、输入、事件和结果 |
| 发现的人 | 评论、直播或互动中出现的用户 | 不等于已经判定的潜客 |
| 潜客 | 已完成分析、可以继续推进的用户记录 | 必须保留来源与判断依据 |
| 证据 | 原始评论、直播弹幕、互动、账号资料、私信或平台回执 | 结论必须能回到证据 |
| 触达回执 | 平台对首次私信动作的最终结果 | 提交发送不等于已触达 |
| 留资 | 从真实私信中识别出的联系方式或明确留资信息 | 必须保留原始消息、识别字段、来源账号和时间 |
| 文件 | 可复用的业务产出，例如 HTML 分析报告 | 文件中心和产品内对话可共同访问 |

## 2. 信息架构与职责

| 页面 | 解决什么问题 | 核心输出 |
| --- | --- | --- |
| 办公室 | 当前哪些 Agent 在工作、做到了哪里 | 工作状态、最近成果、工作录屏和直接对话 |
| 对话 | 咨询全局情况或与特定 Agent 沟通 | 状态解释、结果同步、入口引导和文件附件 |
| Agent 中心 | 选择并启动适合当前业务阶段的 Agent | Agent 介绍、前置条件检查、结构化使用流程 |
| 实时工作 | 以账号为维度查看正在进行的工作 | 运行 Agent、任务进度、异常、账号状态和结果回传 |
| 成果中心 | 沉淀、筛选和推进业务结果 | 潜客线索、发现的人、文件中心和数据漏斗 |
| 对话策略 | 为每个账号配置私信承接方式 | 人设、目标、时间、知识、规则和人工交接边界 |

## 3. 办公室

办公室是 Agent 工作状态与直接对话的入口，不承担任务编排职责。

### 3.1 状态模型

| 产品状态 | 当前界面文案 | 含义 | 用户下一步 |
| --- | --- | --- | --- |
| 工作中 | `工作中` | 当前存在真实运行任务或监听任务 | 查看工作画面、对话或实时工作详情 |
| 空闲中 | `暂时没有任务` | 当前没有运行任务，或任务已暂停、结束、失败后未继续 | 从办公室快捷动作或 Agent 中心发起下一步 |
| 已掉线 | `账号已掉线` | 授权失效、账号登录过期或云电脑离线 | 重新连接账号后恢复工作 |

“暂未获取状态”不属于正常的产品状态。系统临时无法确认状态时，只能作为短暂的读取或恢复过程；没有真实运行证据时，最终回落为空闲中，不能伪装为工作中。

### 3.2 工作台

1. 办公室首页提供五个下一步入口：找一批客户、开始找人、分析候选人、准备私信触达、帮我接待私信。
2. 用户选中 Agent 后，工作台展示当前状态、任务上下文、最近成果和可继续的直接对话。
3. 涉及云电脑的 Agent 包括：抖音获客管家、找客专员、潜客激活专员、私信客服。
4. 上述 Agent 在工作中时，工作台展示云电脑最近一次**成功**工作的回放。回放窗口为 15 秒；没有成功任务时，明确显示“暂无成功工作的录屏”。
5. 客户分析员不以持续云电脑操作为主，其工作台以分析状态、结果和对话为主。

### 3.3 办公室中的 Agent 对话

每个 Agent 都有独立、持久化的对话上下文。对话携带必要的 Agent、账号和任务上下文，并可展示报告等附件。

对话的职责是解释与协作，不是绕过业务流程的执行入口：普通聊天消息不能直接触发找人、分析、发私信或自动回复。用户需要执行业务时，系统应将其带入相应 Agent 的结构化使用流程。

## 4. 对话体系

### 4.1 幕僚长

幕僚长是全局只读运营助手，不是总控执行器。

**可以做：**

- 查看全局 Agent 状态、任务进展和已有成果；
- 解释不同专业 Agent 的职责；
- 根据用户问题，引导至正确的 Agent、实时工作或成果中心入口；
- 解释任务为何阻塞，以及下一步应在哪里处理。

**当前不做：**

- 不创建任务；
- 不拆解目标并派发 Agent；
- 不启动、暂停、恢复、停止或重试任务；
- 不代表用户发送私信、评论或回复客户；
- 不把模糊对话包装成“已经开始处理”。

幕僚长只处理两类请求：

```text
状态查询 -> 读取真实任务与结果快照 -> 返回真实汇总
能力咨询 -> 解释职责边界 -> 引导至正确的专业 Agent
```

### 4.2 执行 Agent 对话

执行 Agent 的对话用于：

- 解释自身能力与输入要求；
- 同步真实任务状态、结果、异常和下一步；
- 查看与该 Agent 相关的历史对话、记忆和附件；
- 将用户带入结构化执行页面。

每个执行 Agent 都具备自身的人设、记忆和任务上下文，但记忆只用于保持该 Agent 的连续协作，不可用于跨账号、跨用户或跨 Agent 擅自外联。

## 5. Agent 体系

当前产品包含一个综合能力 Agent 与四个单能力 Agent。它们共享同一条获客业务链路，但不是上下级组织关系。

```text
找客专员 -> 客户分析员 -> 潜客激活专员 -> 私信客服
```

该链路表示推荐交接顺序，不表示幕僚长在后台自动编排。

### 5.1 抖音获客管家：综合能力 Agent

| 项目 | 说明 |
| --- | --- |
| 定位 | 一站式抖音获客执行 Agent |
| 能力范围 | 找人、分析、首次触达、后续私信承接 |
| 找人范围 | 当前授权账号的评论、直播弹幕和互动 |
| 分析范围 | 基于真实互动证据判断是否值得继续推进 |
| 触达方式 | 在同一授权账号中，通过云电脑逐位完成首次私信并记录平台回执 |
| 后续承接 | 监听新私信和触达后的回复，按照账号策略继续对话或交给人工 |
| 安全边界 | 不读取未授权账号；不使用非公开、非授权信息；不以发送请求代替触达结果 |

综合获客管家面向希望“一条链路跑通”的用户。用户确认长流程后，Agent 可以按既定职责连续处理，但每个阶段的真实结果仍应写回成果中心。

### 5.2 找客专员：收集互动用户

| 项目 | 说明 |
| --- | --- |
| 定位 | 单能力找人 Agent |
| 目标 | 汇总当前账号的互动用户，建立可分析的原始人群池 |
| 数据来源 | 评论区、直播间、账号互动 |
| 输出 | “发现的人”与待分析用户，保留来源、原话、时间和互动证据 |
| 不做什么 | 不判断购买意向；不私信触达；不回扫历史内容 |
| 运行边界 | 仅处理启用后收到的当前授权账号新信号，并进行去重 |

找客专员的结果是“有互动证据的人”，不是自动生成的潜客。其价值是完整地保留可供后续判断的用户池。

### 5.3 客户分析员：判断谁值得推进

客户分析员有两类明确入口。

#### A. 对找客结果进行潜客分析

1. 用户可以在成果中心筛选“发现的人”或已有记录后发起分析。
2. 用户也可以在打开客户分析员时，按账号维度直接加载该账号下已找到的人。
3. Agent 基于来源证据、原始表达和用户配置的分析目标判断是否值得推进。
4. 判断结果写回成果中心：高或中等意向的用户进入`待确认触达`；低价值或不适合推进的用户进入`已归档`。
5. 分析本身不会发送私信，也不会使用未授权联系方式。

#### B. 对公开账号或指定目标生成分析报告

1. 用户可以选择一个或多个公开账号，或描述一个明确的分析目标。
2. Agent 仅基于可见账号资料、作品和公开互动证据完成分析。
3. 产出为 HTML 分析报告。
4. 报告同时沉淀到文件中心，并以附件形式发送到产品内对话。
5. 公开账号分析结果仅用于分析，不提供私信触达。

#### 无数据时的引导

如果当前没有找客专员产出的可分析数据，用户在 Agent 中心点击客户分析员时，系统弹出前置提示：

```text
先完成找客，再分析客户
客户分析员只判断找客专员汇总的互动用户。
当前还没有可分析的数据，先完成找客后会自动带入最新名单。

推荐顺序：找客专员 -> 客户分析员 -> 潜客激活专员
```

主操作为“先使用找客专员”。这是业务依赖检查，不是禁止用户使用独立的公开账号/指定目标分析报告能力。

### 5.4 潜客激活专员：完成首次私信触达

| 项目 | 说明 |
| --- | --- |
| 定位 | 单能力首次触达 Agent |
| 输入 | 客户分析员筛选后的`待确认触达`潜客，或成果中心中用户主动筛选的合格潜客 |
| 输出 | 平台回执、触达状态、首次私信内容和触达时间 |
| 执行方式 | 在用户选择的授权账号云电脑中逐位发送 |
| 核心边界 | 只使用当前账号可发送、来源可追溯、状态为`待确认触达`的潜客 |
| 默认限制 | 单次最多 50 人；单账号每日最多 30 人 |

#### 入口与联动

1. 从 Agent 中心进入时，可按账号直接加载该账号已分析且状态为`待确认触达`的潜客。
2. 从成果中心进入时，用户可筛选符合条件的潜客并携带选择结果进入触达页。
3. 同一账号的潜客会优先带入；其他账号已有`待确认触达`潜客时，系统提示切换发送账号或回成果中心选择。
4. 发起前必须完成：确认发送账号、确认目标名单、填写私信内容、明确发送边界。

#### 无潜客时的引导

潜客激活专员与客户分析员一样必须做前置校验：

| 当前数据 | 提示 | 主操作 |
| --- | --- | --- |
| 有互动用户，但尚未分析出潜客 | `先完成客户分析，再触达潜客` | 先使用客户分析员 |
| 没有互动用户，也没有潜客 | `先完成找客和分析，再触达潜客` | 先使用找客专员 |
| 当前账号无可触达潜客，但其他账号有 | 提示切换发送账号或前往成果中心选择 | 切换账号 / 去成果中心 |

#### 发送确认与真实回执

触达页的最终操作必须是：

```text
确认发送给 N 人
```

而不是“预览私信”。预览可作为发送前的辅助能力，但不能替代最终动作。

点击确认后，系统必须：

1. 校验账号是否已授权且可用；
2. 校验目标仍属于该账号、状态仍为`待确认触达`、来源和身份可追溯；
3. 校验私信内容不为空；
4. 写入用户的明确确认；
5. 在云电脑执行实际发送；
6. 等待平台最终回执并写回成果中心。

发送请求提交后、平台最终状态尚未返回时，显示`等待平台回执`。此时不能标记为`已触达`，也不能无依据自动重试。

### 5.5 私信客服：持续承接已有私信

| 项目 | 说明 |
| --- | --- |
| 定位 | 授权账号的私信监听与承接 Agent |
| 监听范围 | 授权账号收到的新私信，以及首次触达后的用户回复 |
| 目标 | 按账号策略回答问题、推进目标、识别留资和转人工 |
| 输出 | 会话记录、回复状态、留资证据、交接记录 |
| 不做什么 | 不主动联系陌生人；不绕过账号策略；不编造价格、事实或承诺 |

私信客服必须使用对应账号的对话策略。涉及投诉、退款、人工要求、价格、无法确认的事实或超出授权范围的问题，应停止自动推进并转交人工。

## 6. 业务闭环

### 6.1 标准获客链路

| 阶段 | 负责 Agent | 输入 | 输出 | 下一步 |
| --- | --- | --- | --- | --- |
| 找人 | 找客专员 | 授权账号的新评论、直播弹幕、互动 | 有来源证据的互动用户 | 客户分析员 |
| 分析 | 客户分析员 | 互动用户、原话、来源证据、分析目标 | `待确认触达`潜客或归档结论 | 潜客激活专员 |
| 首次触达 | 潜客激活专员 | `待确认触达`潜客、发送账号、私信内容、确认 | 平台触达回执 | 私信客服 / 成果中心 |
| 持续承接 | 私信客服 | 用户回复、账号策略、历史上下文 | 跟进状态、留资、人工交接 | 成果中心 / 对话策略 |
| 成果沉淀 | 成果中心 | 所有状态、证据、报告与留资 | 可筛选线索、转化漏斗、文件资产 | 下轮运营动作 |

### 6.2 交接必须携带的信息

任意下游 Agent 接收上游结果时，至少需要以下字段：

- 来源账号；
- 用户标识；
- 来源类型，例如评论、直播弹幕、账号互动或私信；
- 原始表达和时间；
- 上游任务标识；
- 当前潜客状态；
- 分析结论或触达回执；
- 人工处理、留资和转化信息（如已存在）。

没有这些结构化信息，不应允许下游 Agent 把用户当作可直接触达对象。

### 6.3 不同入口的一致性

用户可以从办公室、Agent 中心或成果中心发起工作，但最终必须进入同一套状态机：

```text
办公室快捷动作 / Agent 中心立即使用 / 成果中心筛选
  -> 对应 Agent 的前置校验
  -> 同一任务与证据模型
  -> 结果写回成果中心
  -> 对话与实时工作同步展示
```

入口不同不应产生两套潜客数据、两套触达记录或两套状态口径。

## 7. 潜客状态与回执口径

### 7.1 潜客主状态

| 状态 | 进入条件 | 含义 | 可继续动作 |
| --- | --- | --- | --- |
| 待分析 | 找客专员已发现互动用户，尚未完成意向判断 | 原始用户池，不等于潜客 | 交给客户分析员 |
| 待触达 | 抖音获客管家发现并分析后自动进入流程 | 自动触达流程正在处理，不需要人工点击“开始触达” | 查看自动任务进展 |
| 待确认触达 | 客户分析员判断值得推进，且该潜客不属于自动获客管家的全流程任务 | 已完成分析，等待用户主动确认首次私信 | 点击“开始触达”交给潜客激活专员 |
| 已触达 | 平台明确返回首次私信成功或送达回执 | 首次触达已被确认 | 等待回复或由私信客服承接 |
| 跟进中 | 用户已回复，或当前正在持续对话 | 正在与该用户保持业务对话 | 私信客服继续承接、人工跟进 |
| 已留资 | 从真实对话中提取到明确联系方式或留资信息 | 留资结果已形成 | 查看留资、转人工或进入成交跟进 |
| 成交跟进 | 已进入人工或业务成交阶段 | 需要继续推进成交 | 人工/业务跟进 |
| 已转化 | 业务确认转化完成 | 漏斗最终成果 | 复盘与统计 |
| 已失效 | 明确无效、拒绝、长期无响应或不再适合推进 | 停止自动推进 | 保留审计记录 |
| 已归档 | 分析认为暂不值得推进 | 不进入触达 | 可在需要时重新分析 |

`等待回复`不是独立的业务目标状态。面向用户的业务表达统一为`跟进中`，它表示当前正在与该用户保持对话或等待其下一轮回应；底层可以保留“已回复/未回复”等辅助字段用于判断和筛选。

### 7.2 触达状态的严格口径

| 过程 | 可展示文案 | 是否可计入“已触达” |
| --- | --- | --- |
| 自动流程已接手 | 待触达 | 否 |
| 客户分析员已判断，用户尚未确认 | 待确认触达 | 否 |
| 用户确认，系统开始执行 | 发送中 | 否 |
| 发送请求已提交，等待平台结果 | 等待平台回执 | 否 |
| 平台确认成功或送达 | 已触达 | 是 |
| 平台明确失败 | 触达失败 | 否 |
| 状态无法确认 | 发送状态未知 | 否，且不自动盲目重试 |

### 7.3 已留资必须突出显示的信息

对于`已留资`用户，详情页和列表必须明确展示：

- 已识别的字段类型，例如微信号、手机号、邮箱或其他明确联系方式；
- 字段值；
- 留资原话或可回溯证据；
- 来源账号；
- 收到时间；
- 消息标识或会话标识；
- 当前承接状态与下一步负责人。

联系人信息不是普通状态标签，必须在详情侧栏或详情页中作为重点业务结果展示。

## 8. 成果中心

成果中心由三部分组成。

### 8.1 潜客线索

潜客线索展示获客、触达、跟进和转化的完整总览。用户可以按状态查看和筛选：

```text
全部潜客 / 待触达 / 待确认触达 / 已触达 / 跟进中 / 已留资
```

每条记录至少展示：客户信息、触达状态、回复状态、留资信息、获客账号、来源、城市、触达时间和可执行操作。

用户可以从潜客线索中：

- 选择`待确认触达`用户进入潜客激活专员；
- `待触达`用户属于抖音获客管家的自动流程，列表右侧不提供人工“开始触达”按钮；
- 查看`跟进中`用户的对话和承接进展；
- 查看`已留资`用户的明确联系方式与原始证据；
- 回到客户分析员重新分析已有用户；
- 查看来源和历史时间线。

### 8.2 顶部转化漏斗

潜客线索顶部统一展示：

```text
获取潜客
  -> 私信触达（触达率）
  -> 客户回复（回复率）
  -> 完成留资（触达留资率）
  -> 转化率
```

漏斗口径：

| 指标 | 计算口径 |
| --- | --- |
| 获取潜客 | 已进入潜客池的有效用户数量 |
| 私信触达 | 有平台成功/送达回执的首次触达用户数量 |
| 触达率 | 私信触达 / 获取潜客 |
| 客户回复 | 已触达后收到用户真实回复的用户数量 |
| 回复率 | 客户回复 / 私信触达 |
| 完成留资 | 已识别明确留资字段的用户数量 |
| 触达留资率 | 完成留资 / 私信触达 |
| 转化率 | 已转化 / 获取潜客 |

任务创建、消息草稿、发送请求或未知回执都不能抬高漏斗指标。

### 8.3 发现的人

“发现的人”保存找客专员收集的原始互动用户与证据。它是客户分析员的输入池，而不是可直接群发私信的名单。

用户可在这里：

- 查看用户来自评论、直播还是账号互动；
- 查看原始表达、来源作品或互动信息；
- 选择用户交给客户分析员；
- 追溯找客任务和来源账号。

### 8.4 文件中心

文件中心沉淀报告类成果，当前重点是客户分析员产生的 HTML 分析报告。

每个文件至少关联：

- 生成 Agent；
- 生成时间；
- 关联账号或分析目标；
- 原始任务；
- 产品内对话附件。

文件中心只沉淀真实产出，不展示未生成的占位报告。

---

## 9. 实时工作

实时工作是账号维度的运行监控页，不是新的任务入口或第二套数据系统。

它展示：

- 当前绑定了哪些账号；
- 每个账号正在使用哪些 Agent；
- 当前任务处于什么阶段；
- Agent 是否工作中、空闲中或已掉线；
- 任务进度、异常和最近结果；
- 任务结果回流成果中心的状态。

模拟数据只能用于演示界面，不能被解释为真实平台数据或真实业务结果。

---

## 10. 对话策略

对话策略按账号隔离。不同账号可以有不同的人设、产品资料、营业时间和私信目标；账号 A 的策略不能自动应用到账号 B。

### 10.1 当前支持的配置

| 配置 | 用途 |
| --- | --- |
| 人设与外显身份 | 决定私信客服的表达方式与身份边界 |
| 自动接待开关 | 决定该账号是否启用自动承接 |
| 工作时间 | 配置星期与每日可接待时间 |
| 对话目的 | 明确本账号希望推进的业务目标与转化目标 |
| 业务资料 | 上传并引用可回答的业务内容 |
| 回复规则 | 约束回复长度、表情、合并等待等行为 |
| 人工处理情况 | 明确哪些问题必须交由人工处理 |

业务资料当前支持文本、表格和结构化资料，例如 TXT、Markdown、CSV、TSV、JSON、XLS、XLSX。

### 10.2 试聊

右侧“试聊”用于测试尚未保存或已保存的策略效果：

- 试聊不会发送到抖音；
- 不会给真实用户产生消息；
- 用于检查人设、目标、资料和交接规则是否合理；
- 用户确认后，保存策略才应用到对应账号的私信客服。

## 11. 授权、风控与人工交接

### 11.1 账号授权

1. 私信发送和监听必须使用用户明确授权的抖音账号。
2. 账号掉线、登录过期或授权失效时，相关 Agent 不得继续执行外部动作。
3. 重新连接后，系统恢复可执行状态，但不应自动重放未知结果的发送动作。

### 11.2 首次触达风控

1. 目标必须是有来源、有身份、状态为`待确认触达`的潜客；抖音获客管家的`待触达`记录不能从人工触达入口发送。
2. 发送账号必须与目标所属账号和来源边界相匹配。
3. 发送前用户必须确认内容和人数。
4. 单次与单日发送量受 Agent 限制控制。
5. 平台回执未知时不自动盲目重试。

### 11.3 私信承接风控

出现以下情况时，私信客服应停止自动推进并转人工：

- 用户明确要求人工；
- 投诉、退款、争议或高风险售后；
- 价格、优惠、交付承诺或其他未被策略明确授权的事实；
- 无法从业务资料确认的内容；
- 涉及敏感信息或超出账号策略边界的问题。

---

## 12. 当前不做什么

为避免产品预期失真，当前版本明确不承诺以下能力：

1. 幕僚长自动创建、拆解和编排执行任务；
2. 未经用户确认的潜客激活专员首次批量私信；抖音获客管家的全流程自动触达属于已授权的自动任务，按其自身运行状态展示；
3. 跨未授权账号读取内容、发送私信或承接会话；
4. 将找客专员收集到的所有互动用户直接当作潜客；
5. 将发送请求、草稿或未知状态当作`已触达`；
6. 对公开账号分析结果提供直接私信能力；
7. 以模拟数据、演示录屏或占位文案代替真实业务成果；
8. 自动编造联系方式、价格、库存、承诺或平台回执。

## 13. 验收清单

| 场景 | 正确结果 |
| --- | --- |
| 没有找客数据，点击客户分析员 | 弹窗引导先使用找客专员 |
| 有互动用户但未分析，点击潜客激活专员 | 弹窗引导先使用客户分析员 |
| 没有互动用户和潜客，点击潜客激活专员 | 弹窗引导先使用找客专员 |
| 从成果中心选择`待确认触达`用户点击“开始触达” | 进入潜客激活专员并带入已选用户，要求用户完成主动确认 |
| 查看抖音获客管家的`待触达`用户 | 显示“自动触达中”，按钮不可点击；进展从自动任务查看 |
| 触达页最终提交 | 按钮为“确认发送给 N 人”，而不是“预览私信” |
| 发送请求已提交但未收到平台回执 | 展示等待平台回执，不计入已触达 |
| 用户回复首次私信 | 潜客进入跟进中，由私信客服按策略承接 |
| 用户留下微信号等联系方式 | 进入已留资，详情突出字段值、原话、来源账号和时间 |
| 客户分析员生成公开账号分析报告 | 报告进入文件中心，并作为 HTML 附件发送到产品内对话 |
| 办公室没有运行任务 | 显示空闲中/暂时没有任务，不默认显示暂未获取状态 |
| 云电脑 Agent 没有成功任务 | 工作台显示暂无成功工作的录屏 |

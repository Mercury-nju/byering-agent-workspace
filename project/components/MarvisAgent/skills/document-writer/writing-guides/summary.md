# 总结梳理类写作规范（summary）

> 适用于 `templates/summary/` 下所有模板（工作总结、述职报告、工作汇报、会议纪要、项目复盘、技术总结、进度汇报、信息提取、教案课件、个人简历、周报等）。
> 与 `SKILL.md` 中的"通用写作规范"**叠加生效**，本文件条目**优先级更高**。

---

## 🔀 两种形态（动笔前先判定，规则不同）

总结类文档在真实任务中存在两种本质不同的形态，**硬约束和写作范式差异极大**，动笔前必须先判定属于哪一种。

| 形态 | 作者视角 | 目的 | 代表模板 | 代表任务 |
|------|---------|------|---------|---------|
| **形态 A · 汇报型总结** | 作者是**当事人** | 向上/向外交代工作成果和问题 | `work-summary` / `debriefing-report` / `weekly-report` / `progress-report` / `project-review` / `resume` / `lesson-plan` | "写 Q3 工作总结"、"写本周周报"、"写项目复盘" |
| **形态 B · 提炼型总结** | 作者是**读者** | 帮下游快速抓住源文档讲了什么 | `knowledge-extraction` / `tech-summary` / `meeting-minutes`（纪要本身是提炼） | "总结这份 PDF 的核心内容"、"整理这次会议要点"、"读书笔记"、"汇总这批文档讲了什么" |

**判定提示**：
- 用户说"总结 / 整理 / 提炼 xxx 文档 / xxx 资料的核心内容" → **形态 B**
- 用户说"写我的 / 我们的 / 项目的 / 本周的总结 / 汇报 / 复盘" → **形态 A**
- 混合场景（既要提炼别人的、又要加自己的汇报）→ 按主导意图判定；若各占一半，**以形态 B 的压缩约束为上限**，避免产物失控

> ⚠️ 两种形态的"自审清单"和"反模式对照表"在本文件末尾**分开列出**，对应形态请对号入座。

# 形态 A · 汇报型总结

## A.核心范式
**从多到少**。将散乱信息提炼为结构化的要点与结论，三条底线：

1. **洞察优先，而非堆砌**：提炼趋势、异常、经验、行动建议，不是罗列完成事项。
2. **量化结果**：用**数据 + 环比/同比/对比目标**说话，拒绝"较大/明显/有提升"等模糊描述。
3. **问题闭环**：每个问题都要附带**根因分析 + 已采取措施 + 后续行动**。

## A.2 分钟可读原则
读者能在 2 分钟内抓住核心是验收底线，三件事保障：

- **TL;DR 前置**：文档开头 3-5 条要点交代最重要结论。
- **状态标识显式化**：🟢 正常 / 🟡 注意 / 🔴 风险；↑↓ 表示环比；P0/P1/P2 表优先级。
- **表格承担数据，段落只写分析**。

## A.量化与对比
- KPI/OKR 一律**表格呈现**：目标值 / 实际值 / 达成率 / 同比或环比 / 状态。
- 关键指标**必须有对比**（环比、同比或对标目标），只给绝对值等于没信息量。
- 未达标指标**必须分析原因并给出改进动作**。

## A.问题闭环的标准句式
`问题描述 → 影响范围 → 根因 → 已采取措施（及效果） → 后续行动（负责人 + 时间节点）`，五要素缺一不可。

- ✅ "Q3 智能客服延期 3 周，影响 Q4 上线；根因为需求 3 次变更未冻结 + 测试资源不足；已推行'冻结+预申请'机制，Q4 全部按期；PM 张三跟进至 2026 Q1。"
- ❌ "项目有些延期，后面会注意。"

## A.规划/计划的 SMART 约束
"下周计划 / 下阶段规划 / 待办事项"每条必须同时满足：具体、可衡量、可指派（有负责人）、相关、有时间节点。

## A.自审清单（汇报型专用）
- [ ] 是否有 TL;DR 前置？读者 2 分钟能否抓住核心？
- [ ] 关键成果是否全部量化？是否有环比/同比/目标对比？
- [ ] 每个问题是否做到五要素闭环？
- [ ] 下阶段规划是否逐条满足 SMART？
- [ ] 🟢🟡🔴、↑↓、P0/P1/P2 是否规范使用？
- [ ] 是否避免了流水账式叙述和"成就通报 + 无反思"式结构？
- [ ] 反思是否有真实不足，而非"能力不足仍需努力"套话？

## A.反模式对照（汇报型专用）
| ✅ 正确 | ❌ 避免 |
|--------|--------|
| "核心支付重构完成，Bug 修复率 ↑40%，P99 从 1.2s→480ms" | "本周完成 5 需求、修 3 个 Bug" |
| "延期因需求 3 次变更未冻结；已建冻结机制，Q4 已按期" | "接口联调有些问题，后续跟进" |
| "周一方案评审→周三实现→周五提测（负责人：李四）" | "下周继续推进项目" |
| TL;DR：🟢 核心成果 / 🟡 风险 / 🔵 下周重点 | 上来流水账列 20 条事项 |
| "复盘发现需求评审粒度过粗，已拆为三级评审" | "深感能力不足，未来仍需努力" |
| KPI 表：目标/实际/达成率/同比/状态 | "本月业绩还不错" |

# 形态 B · 提炼型总结

> ⚠️ **本形态是"总结"二字的字面含义**：把长的变短、把多的变少、把散的变整。**产物必须比源精炼得多，否则就不是总结**。

## B.核心范式（与形态 A 的硬性差异，按优先级）

### B.1 忠实优先于洞察（最高优先级）
- **只能陈述源文档已经说了的事**，不增不减
- **禁止补充**源中没有的维度：战略建议 / 实施保障 / 未来展望 / 风险分析 / 效果评估 / 行动计划……这些是汇报/方案类的套路，**提炼型总结里一律不要**
- 作者不立观点、不做"洞察"、不给"建议"（除非源文档里本就有，此时原样转述并注明"源中指出……"）
- 与形态 A 的"洞察优先"**刚好相反**——提炼型总结的作者是**忠实的传声筒**，不是评论员

### B.2 压缩比硬约束（可计算、可验证）
- **目标产物字符数 ≤ 源字符数 × 20%，建议 10%-15%**
- 动笔前先读一遍源、记录源字符数 S；产物控制在 `[0.10×S, 0.20×S]` 区间内
- 若源含多份文档（如"总结这 5 份调研报告"），S 按**合计字符数**计
- **超限即失败**：自审时若发现产物即将超限，优先删除"源里没说的话"（自造建议/展望/保障/意义陈述），**不要**通过压缩源内容让路给自造内容

### B.3 维度点先行，而非章节先行
- **不走"章节 + 每章 2-3 条关键问题"的结构**（那是路径 B 的报告范式）
- 按源的自然主题拆 **4-7 个维度点**（维度 = 源中反复出现的一类话题）
- 每个维度点用 **3-8 句话 + 关键数据/举例** 讲完即止
- 文档结构推荐："一句话源定位" + "维度点 1-N"（每个维度点用二级标题），可选末尾附一张"源信息速览表"
- 表格、要点列表优先于段落叙述；**不写**长段落分析

### B.4 禁止"扩写反模式"
出现以下章节/段落**一律删除**（`meeting-minutes` 的"行动项"除外，那是纪要的固有组成）：

| 扩写反模式章节 | 为什么要删 |
|---------------|-----------|
| 执行摘要 / TL;DR | 提炼型总结**整篇就是摘要**，再套一层 TL;DR 是套娃 |
| 背景与意义 / 编写目的 | 源文档里没讲的背景，不要自己补 |
| 战略建议 / 优化建议 | 源中没有的建议 = 自造，违反 B.1 |
| 实施保障 / 行动计划 / 下一步规划 | 同上，属于汇报/方案类套路 |
| 效果评估 / 风险分析 | 同上 |
| 未来展望 / 结语寄语 | 注水，用户要的是"源讲了什么"，不是"你怎么看" |
| 每个维度后加一段"本章小结" | 总结里套小结是套娃，删 |

### B.5 每个维度点只保留三件事
- **是什么**：源中该维度讲的核心事实/观点（一句话概括）
- **关键数据或代表性举例**：能体现该维度信息密度的 1-2 个数据点或引文
- **源的结论**（如有）：源文档自己给出的结论，原样转述；**源没给就不要凑**

## B.自审清单（提炼型专用，优先级高于通用底座）
- [ ] **压缩比**：产物字符数 ≤ 源字符数 × 20%？超了就删"自造内容"，不要删源内容
- [ ] **忠实度**：每个陈述是否都能在源中找到对应原文？是否存在源中没有的维度/章节？
- [ ] **禁扩写**：是否出现"执行摘要 / 战略建议 / 实施保障 / 效果评估 / 未来展望 / 本章小结"等扩写反模式？
- [ ] **维度点结构**：是否按 4-7 个维度点组织，而不是写成"6 章大报告"？
- [ ] **每点精简**：每个维度点是否控制在 3-8 句话？有没有为"显得充实"而展开冗长论述？
- [ ] **作者身份**：通读一遍，文中有没有"本文建议 / 我们认为 / 应该 / 未来应……"等作者立论的措辞？有就删
- [ ] **可回溯**：关键数据/引文是否标注了来源（哪份源文档的哪部分）？

## B.反模式对照（提炼型专用）
| ✅ 正确 | ❌ 避免 |
|--------|--------|
| "源文档《XX 调研报告》提出三类技术路线：A/B/C。其中 A 适用于 xxx 场景（P12），B 的实测延迟为 200ms（P34）……" | "本文总结了调研报告，并提出应采用 A 路线的建议" |
| 4-7 个维度点、每点 3-8 句、整篇 2000-4000 字（源 2 万字） | 6 章大报告、每章 TL;DR + 分析 + 小结，整篇 2 万字 |
| 源没讲实施保障 → 不写这一章 | 源没讲实施保障 → LLM 补一章"实施保障与风险控制" |
| "源指出 A 方案延迟 200ms、吞吐 3000 QPS（第 3 章）" | "A 方案性能优异，适合高并发场景"（模糊+自造评价） |
| 末尾附"源信息速览表"：文档名/作者/日期/页数/核心主题 | 末尾附"总结反思与未来展望" |
| 作者保持传声筒身份，不立观点 | 文中频繁出现"建议 / 应当 / 未来需要 / 我认为" |

## 📎 混合场景处理（少数情况）

若单次任务同时涉及两种形态（如"把这 3 份周报整合成一份季度总结"——既是提炼又是汇报），按主导意图判定：

- **输入是自己的 / 团队的产出、产物供上级审阅** → 主导为形态 A，但每份源的提炼部分遵守 B.1 忠实原则
- **输入是外部文档 / 他人产出、产物供读者了解源内容** → 主导为形态 B，允许末尾附一节"核心要点速览"但不扩写建议

判断不清时，**以形态 B 的压缩比为上限**（产物 ≤ 源 × 20%），避免走成 2 万字大报告。

# 调研分析类写作规范（research）

> 适用于 `templates/research/` 下所有模板（行业调研、竞品分析、财务分析、舆情分析、人才盘点、技术调研、合规分析、满意度分析等）。
> 与 `SKILL.md` 中的"通用写作规范"**叠加生效**，本文件条目**优先级更高**。

## 核心范式
**先调研、后分析、再结论**。以客观数据和事实为支撑，三条底线：

1. **来源可追溯**：关键数据和事实**必须注明来源**，关键来源附 URL；优先多源交叉验证。
2. **事实与预测分离**：已发生的事实、他方观点引用、本文预测必须**明确区分**（用小标题、引用块或"预计/可能/若..."措辞）。
3. **覆盖无遗漏**：声明过的维度，每个对象/每个周期都要覆盖；数据缺失**显式标注 "N/A / 未提供"**，不得悄悄跳过。
   > ⚠️ **覆盖 ≠ 开章**：覆盖是在**同一章内用多个小节 / 表格 / 图表**完成的，不是"每个维度单独开一个章节"。例如 6 个满意度维度应在"满意度分析"一章内分 6 个小节（或一张对比表）呈现，而不是拆成 6 章。

## 来源可靠性分层
| 层级 | 示例 | 使用建议 |
|------|------|---------|
| 一级 | 公司年报/季报、政府统计、监管数据 | 关键财务 & 宏观数据首选 |
| 二级 | 权威研究机构（Gartner/IDC/麦肯锡/艾瑞等）、行业白皮书 | 市场规模、行业趋势首选 |
| 三级 | 头部财经媒体（FT/WSJ/彭博/36kr 等） | 事件类信息，需交叉验证 |
| 四级 | 自媒体、论坛 | 仅作线索，**禁止**直接引用为数据来源 |

> 数据时效：除历史分析外，核心数据应在 **12 个月内**；过时数据需显式说明。

## 章节结构（分析类通用合并原则）

> 分析类文档的章节数**严重过拆**是最常见的质量问题。本节规则**优先级高于各模板的章节骨架**：模板章节仅作为候选池，实际成章与否由本节判定。

### 默认章节数：3-5 章（不含附录）

大多数日常分析任务（团队盘点、费用分析、竞品对比、满意度调研、成绩分析等）的用户诉求只有 3-4 条，对应结构应为：

```
必含 3 章：全貌/概况  →  核心分析（含所有维度小节）  →  结论/建议
可选 +1-2 章：执行摘要、附录（仅在触发下方条件时开章）
```

### 三条硬合并规则

**规则 1：同一批数据的不同切片视角，合并为一章**

| ❌ 过拆（独立成章） | ✅ 合并（一章多小节） |
|---|---|
| "整体满意度" + "维度分析" + "分群对比" + "开放反馈" 4 章 | **"满意度分析"一章**，内含 4 个小节 |
| "数据总览" + "矩阵分析" + "继任分析" + "风险分析" 4 章 | **"人才盘点分析"一章**，内含 4 个小节 |
| "费用总览" + "结构分析" + "趋势对比" + "异常分析" 4 章 | **"费用分析"一章**，内含 4 个小节 |

**判定方法**：若两章用的是**同一批数据、同一类对象、只是切片视角不同**，就必须合并；仅当数据源、对象、时间范围之一发生根本切换时才独立成章。

**规则 2：摘要章和附录章默认不开**

- **执行摘要**：默认不单独成章，改为文档开头一段 3-5 行的"核心发现"引语。仅当**用户明确要求写给高层汇报**、或文档 ≥ 6 章 时，才单独成"执行摘要"章。
- **附录**：默认不单独成章，数据表内嵌到对应分析章。仅当**原始数据表 ≥ 3 张且每张 > 10 行**、正文内嵌会打断阅读时，才单独成"附录"章。
- **背景与方法 / 对象概况**：默认合并到"全貌/概况"章的首节，不单独成章。

**规则 3：章节数 > 5 章必须逐章验证**

当草拟大纲超过 5 章时，对每一章回答：**"这一章对应用户原话中的哪一句诉求？"** 答不出来、或多章共用同一条诉求 → 合并。

### 示例对照

| 用户需求 | ❌ 过拆大纲（模板硬套） | ✅ 合理大纲（需求驱动） |
|---|---|---|
| "分析 Q3 费用，哪里超支、下季怎么控" | 摘要 / 总览 / 结构 / 趋势 / 异常 / 建议 / 附录（7 章） | 费用全貌 / 超支与异常分析 / 控费建议（3 章） |
| "盘点团队 15 个人的能力和风险" | 摘要 / 背景方法 / 数据总览 / 矩阵 / 继任 / 风险 / 建议 / 附录（8 章） | 团队全貌 / 关键人才与风险分析 / 发展建议（3 章） |
| "比较 3 款 SaaS 工具选型" | 摘要 / 比较框架 / 对象概况 / 多维对比 / 综合评估 / 建议（6 章） | 比较框架与对象 / 多维对比分析 / 选型建议（3 章） |
| "分析全班 40 人成绩并给个性化建议" | 摘要 / 背景 / 整体 / 科目 / 排名 / 个体 / 分群 / 建议（8 章） | 整体表现 / 个体分析（40 人分层） / 改进建议（3 章） |

## 分析框架（按需选用，不空挂标签）
PEST/PESTEL、波特五力、SWOT、价值链、TAM/SAM/SOM、4P/4C、波士顿矩阵等。套框架就要有框架内每一项的实质分析。

## 执行摘要（按需，不强制单独成章）
- 默认做法：文档开头一段 3-5 行"核心发现"引语，**不单独成章**。
- 单独成章的触发条件：用户明确要求汇报给高层 / 文档 ≥ 6 章。
- 若单独成章，须：简明扼要、可独立阅读、覆盖 3-5 条关键发现 + 关键数据 + 明确结论建议。

## 数据与图表
- 趋势→折线图、对比→柱状图/表格、占比→饼图、多维能力→雷达图、分布→散点图。
- 每张图必含：**标题 + 坐标轴标签 + 数据来源 + 编号**，正文用编号引用。
- 派生数值（比率、增长率）必须可追溯到原始数据与计算公式。
- 基准值（满分/目标/预算）**不得编造**；原始数据未提供时标注 "未提供" 而非自行填充。

## 调研类自审清单
- [ ] **章节数是否 ≤ 5 章（不含附录）？超出时每章能否对应用户原话中的一条诉求？**
- [ ] **是否误把"同一批数据的切片视角"拆成了多章（应合并为一章多小节）？**
- [ ] **是否为"执行摘要 / 背景方法 / 对象概况 / 附录"单独开了章？不满足触发条件时应合并或删除。**
- [ ] 关键数据是否都有来源？关键来源是否有 URL？
- [ ] 核心数据是否在 12 个月内？
- [ ] 是否做到事实与预测分离？
- [ ] 声明的维度是否对每个对象/周期都完整覆盖？缺失处是否显式标注？
- [ ] 是否存在凭空填写的基准值？
- [ ] 分析框架是否有实质分析而非只贴标签？
- [ ] 是否优劣并述，无"报喜不报忧"？

## 反模式对照
| ✅ 正确 | ❌ 避免 |
|--------|--------|
| "据 IDC《2025 中国 AI 市场白皮书》，市场规模 XX 亿，YoY +32.1%（2025H1）" | "市场规模增长很快" |
| 原始无目标值 → 达成率列标 "未提供" | 没有目标值 → 自己填 100 |
| SWOT 每项都展开 2-3 句事实分析 | "优势：强；劣势：弱"这类标签填充 |
| 事实/预测分写："2024 营收 120 亿"、"若保持节奏 2025 预计 150 亿" | "营收 120 亿，2025 会到 150 亿" |
| 竞品 A/B/C 在全部 6 个维度对比，缺失标 N/A | 只对比 3 个维度，其余不提 |
| 图 1 柱状图：标题 + 轴标签 + 数据来源 + 正文引用 | 图表无标题、无来源、未在正文引用 |

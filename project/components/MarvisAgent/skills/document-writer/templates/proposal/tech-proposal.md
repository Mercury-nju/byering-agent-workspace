# 技术方案模板

## 章节结构

### 第1章 方案概述
- **写作要点指导**：一段话概述方案的核心目标与关键设计决策，列出方案的关键指标/约束（如性能目标、成本上限、时间节点），说明本文档的目标读者与阅读建议

### 第2章 背景与需求分析
- **写作要点指导**：阐述业务背景与技术痛点，分析当前系统/方案的不足，明确需求列表（功能性需求 + 非功能性需求），列出方案的约束条件与假设前提

### 第3章 方案设计
- **写作要点指导**：阐述整体架构设计（可使用架构图/Mermaid 图），详细说明核心模块的设计思路与交互流程，说明关键技术选型及选型理由，给出数据模型设计（如有数据库变更）。这是全文最核心的章节

### 第4章 方案对比（可选）
- **写作要点指导**：如果存在多个候选方案，使用表格对比各方案的优劣势，说明最终选择的方案及选择理由，分析放弃方案的主要缺陷

### 第5章 接口与协议设计
- **写作要点指导**：定义核心 API 接口（请求/响应格式），说明模块间的通信协议与数据流向，列出外部依赖与接入方式

### 第6章 实施计划
- **写作要点指导**：将实施过程分为阶段（如灰度、全量），每个阶段明确里程碑、交付物、时间节点，说明测试策略（单元测试、集成测试、压力测试），制定回滚方案

### 第7章 风险评估与应对
- **写作要点指导**：使用表格列出潜在风险（技术风险、依赖风险、性能风险等），评估每个风险的概率与影响程度，给出对应的应对/缓解策略

### 第8章 监控与运维
- **写作要点指导**：定义核心监控指标与告警规则，说明日志策略与问题排查方式，制定上线后的观察周期与验收标准

## 写作要求
- 语言风格：半正式、技术专业，逻辑严谨
- 数据要求：性能指标需有量化目标；架构图使用 Mermaid 语法或清晰的文字描述；接口定义使用代码块格式
- 特殊约束：方案设计需考虑可扩展性和向后兼容性；风险评估不能只列风险不给应对策略；实施计划必须有回滚方案

# 需求文档模板

## 章节结构

### 第1章 文档概述
- **写作要点指导**：使用表格记录文档基本信息（产品名称、版本号、需求编号、作者、日期、审批人），概述本次需求的核心目标与价值，说明文档的读者与使用方式，标注需求优先级（P0/P1/P2）

### 第2章 背景与目标
- **写作要点指导**：说明需求的业务背景（为什么要做），分析用户痛点与机会（解决什么问题），定义需求目标（使用 SMART 原则量化），明确成功指标（上线后如何衡量效果）

### 第3章 用户与场景分析
- **写作要点指导**：定义目标用户角色（用户画像），描述核心使用场景（用户故事格式：作为[角色]，我想[操作]，以便[价值]），梳理用户操作流程（主流程 + 异常流程），标注用户体验的关键路径

### 第4章 功能需求
- **写作要点指导**：按功能模块分组描述，每个功能包含：功能编号、功能名称、功能描述、输入/输出、业务规则、优先级，使用表格呈现功能清单总览，复杂功能配以流程图或状态图，标注功能之间的依赖关系

### 第5章 非功能需求
- **写作要点指导**：定义性能要求（响应时间、吞吐量、并发数），定义安全要求（认证、授权、数据加密），定义兼容性要求（浏览器、设备、系统版本），定义可用性要求（SLA、降级策略），其他约束（数据量、存储、合规等）

### 第6章 交互设计说明
- **写作要点指导**：描述关键页面的布局与信息架构，说明核心交互流程（按钮行为、页面跳转、状态变化），标注异常状态的处理方式（空态、加载态、错误态），可引用原型图/线框图（如有）

### 第7章 验收标准
- **写作要点指导**：为每个功能定义验收条件（Given-When-Then 格式或检查清单），定义测试场景覆盖要求，明确上线前必须通过的前置条件，标注回归范围

### 第8章 排期与里程碑
- **写作要点指导**：按优先级排列需求实现顺序，给出各阶段的里程碑与预期时间，标注依赖项与风险项

### 附录
- **写作要点指导**：术语表、业务规则明细、数据字典、参考资料

## 写作要求
- 语言风格：精确、无歧义，面向开发/测试团队
- 数据要求：功能描述需完整覆盖正常流程与异常流程；数值型要求需有具体指标（不能只说"快"）；优先级标注统一使用 P0/P1/P2
- 特殊约束：需求描述要具体到可实现、可测试、可验收的粒度；避免模糊表述（如"友好的界面""快速响应"）；功能之间的依赖和冲突需显式标注

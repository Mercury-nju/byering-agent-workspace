# 看板定制设计

## 目标

将现有项目组结果看板升级为可浏览、可定制的销售业务看板工作台。外围采用参考图中的白底、宽留白、细描边圆角卡片和黑色主按钮；右上角提供“对话创建”入口，详情页提供“修改 / 整理 / 全屏 / 刷新”。

## 用户流程

1. 用户打开“看板”后看到看板目录卡片。每个卡片来自真实项目组，预览使用已有的线索、触达、回复、转化和交付数据。
2. 用户点击卡片进入项目看板详情。详情保留现有结果指标、明细、文件和趋势图，同时加入操作工具栏。
3. 点击“修改”进入同页视图编辑态：修改看板名称；选择主题色、强调色、页面排版和信息密度；勾选要展示的组件；右侧实时预览视觉结果。任务、Agent 状态和项目数据不在此处编辑。
4. 点击“保存修改”写入 `localStorage`，立即回到详情态；取消恢复上一次保存的配置。
5. “整理”按任务状态将任务归入对应列；状态枚举为 `todo`、`doing`、`approval`、`done`，默认分别映射到“待跟进”“触达中”“待审核”“已完成”。自定义列按以下关键字数组顺序匹配，多个列命中时取列顺序最靠前者：`todo=["待","跟进","线索"]`、`doing=["进行","触达","执行"]`、`approval=["审核","审批","确认"]`、`done=["完成","转化","签约"]`。无法匹配的任务保留原列；原列已删除时放入第一列。“刷新”重新读取项目组数据；“全屏”切换看板根节点的全屏展示。
6. “对话创建”选择当前排序后的第一个项目组（无项目组时使用固定 `seed-sales-ops` 销售模板）进入 Agent 对话画布。用户描述业务主题、视觉风格、排版和信息重点后，Agent 生成真实业务数据的看板视图草案；用户可确认生成并保存到该项目组，或进入视图编辑。它不创建新的 gateway 项目组，也不修改原任务对话。

## 数据模型

```js
{
  title: "潜在客户拓展项目组",
  columns: [
    { id: "todo", title: "待跟进", tasks: [{ id, title, detail, status }] },
    { id: "doing", title: "触达中", tasks: [] },
    { id: "approval", title: "待审核", tasks: [] },
    { id: "done", title: "已完成", tasks: [] }
  ],
  view: {
    theme: "light",
    layout: "dashboard",
    density: "comfortable",
    accent: "blue",
    components: ["records", "metrics", "files", "trend", "tasks"]
  },
  updatedAt: "ISO timestamp"
}
```

配置按项目组 `room.id` 存储在 `salebuddy.kanban.custom.v1`，完整 envelope 为 `{ version: 1, boards: { [roomId]: boardConfig } }`。board 配置包含业务展示数据和独立的 `view` 视图配置：主题、排版、密度、强调色与组件集合。单个 room 配置损坏只回落该 room 的销售模板，不影响其他 room。无 gateway 或无项目组时使用固定 `seed-sales-ops` 销售运营模板，确保目录仍有真实业务内容。

看板中的业务数据和 `task-store` 的任务动态保持关联。视图编辑不会改写原任务；但业务组件上的“推进线索 / 生成复盘 / 整理交付 / 分析趋势”等操作会为当前项目组创建真实任务，并打开现有 Agent 任务对话。任务状态由 `task-store` 写回，详情底部的任务动态通过订阅和轮询回显进行中、待审批和已完成，并可回到任务对话。

编辑态存在未保存修改时，轮询暂停；取消、返回或关闭页面直接丢弃草稿并恢复最近一次保存配置，刷新按钮在编辑态不可用。全屏 API 不可用时在看板根节点加 `sb-dash-focus` 聚焦样式，退出按钮恢复正常布局。

## 视觉与可访问性

- 目录：`看板` + “定制主题，搭一块属于你的看板”，2 列响应式卡片网格；卡片显示业务预览、项目组名、组件数量。
- 详情：白色工具栏按钮，主操作使用黑色填充；视图编辑态使用浅灰编辑画布，左侧控制视觉参数，右侧展示真实数据的实时预览。
- 所有图标按钮有 `aria-label`，可聚焦控件有 `:focus-visible`，按钮使用稳定尺寸避免编辑时布局跳动。
- 640px 以下改为单列，视图编辑控制面板和预览不产生横向溢出。

## 边界与错误处理

- 无 gateway 时仍显示业务模板，保证看板目录和定制流程可用。
- `localStorage` 不可用时使用内存配置，页面内仍可编辑。
- 看板始终至少保留一列；删除最后一列按钮不可用，删除其它列前要求确认，列内任务随列一起删除。
- 全屏 API 不支持时降级为页面内“聚焦模式”。

## 验证

- 保留现有看板、导航和办公室测试。
- 新增纯函数测试覆盖：默认模板、配置读写回落、整理任务、列/任务 CRUD。
- 手动验证：目录卡片、详情操作、编辑保存/取消、刷新后持久化、窄屏布局。

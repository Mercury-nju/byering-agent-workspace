# SaleBuddy 侧边导航重排设计

日期：2026-08-10  
状态：已选择视觉方案 A，待规格确认后实施

## 目标

把当前由多套原生与注入节点拼接而成的侧边栏，整理为一条稳定、自然的任务导航。调整仅作用于侧栏的信息层级、间距、状态与折叠行为，不改变任何业务页面、项目组数据或办公室主体。

## 已确认方向

采用“分组收纳”方案：

```text
SaleBuddy
[ ＋ 新建任务 ]
[ 搜索（原生存在时保留）]

工作
┌ 办公室 · 2 个项目
│  ● 潜在客户拓展        当前
│  ○ 触达内容共创
└
  看板
  通讯录
[ 最近任务（存在历史会话时保留）]

能力与资产
  技能广场
  Agent 广场
  文件中心
  资源中心

────────────
  知识库            ▾
    文档
    记忆
```

图中的两个项目组是当前模拟数据示例；实际必须展示 gateway 返回的全部实时项目组。

知识库默认收起态为：

```text
────────────
  知识库            ▸
```

进入文档或记忆后的强制展开态为：

```text
────────────
  知识库            ▾
    文档             当前
    记忆
```

## 信息架构

### 顶部固定区

- SaleBuddy 字标保持现有品牌位置，缩短它与主操作之间的垂直距离。
- “新建任务”是侧栏唯一主操作，使用深色实底与白色图标、文字。
- 主操作与普通导航项不再共享选中态样式。
- 原生搜索入口如果存在，保留在主操作与“工作”分组之间，不做代理或改写。

### 工作区

- “办公室”是项目协作入口，同时也是项目组的父级。
- 办公室块显示实时项目组数量，并在内部展示全部实时项目组。
- 当前项目使用绿色状态点与“当前”标记；其他项目使用中性状态点。
- 看板、通讯录与办公室保持同一一级导航基线。
- 项目组保留现有切换行为，办公室入口保留现有页面行为。
- 原生历史会话列表非空时保留在工作入口之后，并增加“最近任务”弱标题；空态继续隐藏。

### 能力与资产区

- 依次排列技能广场、Agent 广场、文件中心、资源中心。
- 四项使用统一行高、图标盒尺寸、左右内边距与 hover/active 反馈。
- 不再为原生入口和注入入口使用不同的段间距。

### 知识库区

- 知识库固定沉在可用空间底部，以细分隔线与高频工作入口分开。
- 无激活子项时默认收起，只显示“知识库”一级入口；父项使用 `aria-expanded="false"`，子项容器设置 `hidden`，箭头向右。
- 点击知识库切换用户偏好的展开状态；展开时使用 `aria-expanded="true"`，移除 `hidden`，箭头向下。
- 进入文档或记忆时强制展开并标记相应子项，激活期间父项不可收起；离开知识库后恢复用户上一次非激活折叠状态。

## 视觉规范

- 导航一级行高：40px；同组相邻间距：2–4px。
- 项目子项行高：32px；相对一级入口缩进 28px。
- 一级图标盒：20px；文字与图标间距：10–11px。
- 分组标题使用 10–11px 中性灰、较宽字距，不参与点击。
- 活动态使用中性灰底和 9px 圆角，不使用大面积阴影。
- 办公室项目块使用轻微灰底承载父子关系，避免每个项目各自出现大胶囊。
- 字体沿用产品现有中文字体栈，不额外引入网络字体。
- 动效只保留 120–160ms 的背景、颜色和折叠过渡。

## 现有入口处置矩阵

| 入口 | 新位置 | 处理方式 |
| --- | --- | --- |
| SaleBuddy 字标 | 顶部 | 保留现有注入，仅调整周边间距 |
| 新建任务 | 顶部固定区 | 保留原生节点与点击，不做代理 |
| 搜索（若存在） | 新建任务下方 | 保留原生节点与点击，不做代理 |
| 办公室 | 工作区首项 | 保留原生节点，统一样式 |
| 项目组 | 办公室内部 | 由 `office-switch.js` 继续唯一持有数据与渲染；显示全部实时项目组 |
| 历史会话列表 | 工作区末尾 | 非空时保留，增加“最近任务”弱标题 |
| 看板 | 工作区 | 隐藏重复原生行，代理行转发到实时原生行 |
| 通讯录 | 工作区 | SaleBuddy 自定义入口，行为不变 |
| 技能广场 | 能力与资产区 | 隐藏重复原生行，代理行转发到实时原生行 |
| Agent 广场 | 能力与资产区 | SaleBuddy 自定义入口，行为不变 |
| 文件中心 | 能力与资产区 | SaleBuddy 自定义入口，行为不变 |
| 资源中心 | 能力与资产区 | SaleBuddy 自定义入口，行为不变 |
| 原生“应用” | 不展示 | 延续当前明确隐藏策略，不新增删除逻辑 |
| 原生“文档” | 不展示 | 由底部“知识库 → 文档”替代，避免与自定义文档重名；明确授权隐藏 |
| 原生“图库” | 不展示 | 当前 SaleBuddy 工作流无图库页面，明确授权隐藏，不改变底层数据 |
| 原生“此电脑”及二级项 | 不展示 | 由“文件中心”和员工“云电脑”入口替代，明确授权隐藏，不改变底层数据 |

上述原生本地数据项都是条件性入口：无论当前运行模式是否渲染，都由 `sidebar-customization.js` 按精确文案隐藏。搜索与历史会话不在隐藏名单中，必须保留原点击行为。

## 模块职责与事件契约

### `nav-framework.js`

- 唯一负责导航分组、代理入口、active 状态、知识库折叠与侧栏生命周期。
- 不读取 gateway 项目数据，不复制项目组 DOM，不重新实现办公室切换。
- 每次代理点击前重新查找当前已连接的原生目标节点，避免持有 React 重渲染后的失效引用。
- 看板定位兼容“自动任务”和“看板”两个文本状态，但只有实时原生行带 `data-sb-kanban="1"` 时代理入口才可用；`kanban.js` 尚未接管或节点被 React 替换时必须设置 `aria-disabled="true"`，不得转发到原生自动任务页。
- 原生目标缺失时给代理行设置 `aria-disabled="true"` 并阻止转发；目标恢复后自动解除。

### `office-switch.js`

- 继续唯一持有 `{ rooms, activeRoomId }` 及项目切换逻辑。
- 允许增加办公室项目数量徽标、适配父子容器样式和导航状态通知，但不向 `nav-framework.js` 复制房间数据。
- 项目切换完成后触发现有原生办公室导航，并发送统一导航状态通知。

### `kanban.js`

- 继续唯一持有看板页面 `pageOpen` 状态。
- 打开、关闭时发送统一导航状态通知，使代理看板入口可可靠同步 active。

### 导航状态通知

- 固定事件名为 `salebuddy:navigation-state`，派发目标和监听目标均为 `document`：

  ```js
  document.dispatchEvent(new CustomEvent("salebuddy:navigation-state", {
    detail: { mode, active }
  }));
  ```

- `mode` 只允许 `newTask | office | kanban | skills | contacts | agentSquare | files | resources | kbDocs | kbMemory`；`active` 必须是布尔值。
- reducer 规则：收到 `{ active: true }` 时用 `mode` 替换当前 active；收到 `{ active: false }` 时仅当 `mode` 仍等于当前 active 才清除，防止旧页面延迟关闭误清新页面状态。
- 办公室、项目组、看板、技能广场、自定义页面和原生导航均通过同一状态入口清理旧 active。
- `nav-framework.js` 观察实时原生行的 active class 与 `aria-current` 变化；React 路由、程序化导航或浏览器返回导致办公室/技能广场状态变化时，观察器按相同契约派发状态，而不依赖鼠标点击。
- 任一时刻仅一个一级入口或一个知识库子项具有 `.sb-nav-on` 与 `aria-current="page"`。

## 生命周期与幂等

- 文档级只允许一个活动实例：模块保存当前实例，侧栏根使用 `data-sb-nav-owner` 标记，样式节点使用固定 ID。
- 重复调用 `mountNavFramework()` 时先返回现有活动实例，不重复添加节点、样式、观察器或点击监听。
- `unmount()` 只执行一次：删除代理节点和 owner 标记，恢复被隐藏原生入口，移除样式、观察器与所有事件监听。
- 再次 mount 必须创建一个干净的新实例。
- 观察器锚定能够覆盖侧栏滚动根的稳定祖先；整棵滚动根被 React 替换后，重新解析锚点、恢复分组和代理绑定。
- 所有转发监听仅绑定在代理节点自身，保证单次点击最多转发一次。

## 实现边界

- 允许修改 `project/src/salebuddy/ui/nav-framework.js`、`office-switch.js`、`kanban.js`、`sidebar-customization.js`、必要的导航测试与 `project/package.json` 测试脚本。
- 不编辑冻结办公室 bundle；完整性测试必须继续通过。
- 不改项目组、看板、通讯录、文件中心、资源中心和知识库的数据接口。
- 原生“办公室 / 看板 / 技能广场”入口通过实时 DOM 解析与事件桥接继续工作，不复制业务逻辑。
- 现有 React 管理节点不做跨容器搬移；需要新结构时由 SaleBuddy 源码层注入代理入口，并隐藏重复原生入口。
- 观察器必须保持幂等，重新渲染后不得重复生成分组或导航项。

## 状态与异常处理

- 原生侧栏尚未挂载时继续等待，不生成残缺导航。
- 原生入口短暂缺失时，代理入口设置 `aria-disabled="true"` 并保持不可用；节点恢复后自动重新绑定。看板即使文本节点已恢复，也必须等待目标行重新出现 `data-sb-kanban="1"`。
- 打开自定义页面时仅一个入口具有 active 状态。
- 点击新建任务、办公室、看板、技能广场或任一程序化导航时，通过统一状态入口清除旧 active。
- 项目组为空时，办公室块只显示“暂无项目”，不保留空白缩进。

## 验收标准

1. 核心入口顺序与 ASCII 结构一致；搜索和最近任务仅在原生内容存在时出现在矩阵规定位置。
2. 所有一级代理行计算高度为 40px，图标盒为 20px；一级文字左边界误差不超过 1px。项目子项高度为 32px，较一级文字缩进 28px（误差不超过 1px）。
3. 项目组只作为办公室二级内容出现。
4. 知识库默认收起，文档或记忆激活时自动展开。
5. 新建任务、搜索（若存在）、办公室、全部项目组、历史会话（若存在）、看板、技能广场、通讯录、Agent 广场、文件中心、资源中心、文档和记忆均可正常进入原有目标；条件性原生应用、文档、图库、此电脑及其二级项不展示。
6. 任意重复 mount 及连续三次整棵侧栏替换后，每个 `data-sb-*` 入口、分组和固定 ID 样式节点均恰好一个；单次点击只转发一次。unmount 后代理、隐藏样式、owner 标记与监听全部移除，再次 mount 可正常恢复。
7. 在 1280×800 与 1440×1000 两个视口验证：侧栏无横向滚动；800px 高度下知识库可通过纵向滚动到达，新建任务保持在原固定区且不被遮挡。
8. 办公室冻结文件完整性检查与完整测试套件通过。

## 测试策略

- 将可纯测试的导航蓝图、active reducer 和知识库折叠 reducer 从 DOM 操作中分离，覆盖入口顺序、动态项目数量/空态、折叠优先级与 active 唯一性。
- 增加最小 DOM 行为测试夹具，验证每个代理恰好转发一次、原生节点缺失/恢复、连续三次侧栏根替换、多次 mount/unmount 和 owner 标记清理。
- 覆盖看板 ready 前禁用、`data-sb-kanban="1"` 出现后启用、接管节点替换后重新禁用，以及不可误入原生自动任务页。
- 覆盖 `salebuddy:navigation-state` 的事件名、document 派发目标、detail 枚举和 reducer 竞态：过期 `{ mode, active: false }` 不得清除较新的 active。
- 覆盖搜索与历史会话原点击各只执行一次，并验证条件性原生应用、文档、图库、此电脑入口在出现时被隐藏。
- 导航测试命令接入 `npm run test:all`，不得只作为手工命令存在。
- 运行导航相关测试和 `npm run test:all`。
- 使用本地浏览器在常规桌面高度与较矮窗口各检查一次：对齐、滚动、active 状态和项目组切换。

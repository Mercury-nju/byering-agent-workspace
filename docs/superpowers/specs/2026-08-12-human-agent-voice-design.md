# 数字员工真人化对话设计

## 目标

数字员工开始任务后，以活泼亲切的第一人称进入对话。用户看到的是同事主动接活、开工、同步和交付，不再是 `SUB_START`、`Executor`、`Agent 已接受任务` 等协议播报。

## 用户可见对话

- 幕僚长仍负责拆解和分派，但技术事件只在内部状态机保留。
- 每位员工第一次出现时主动进场，包含自然语气词、对任务的理解和下一步动作。
- `sub-start` 作为唯一进场消息；紧随其后的 `sub-accepted` 与 `sub-started` 只更新进度状态，不再生成重复气泡。
- 过程日志改写为第一人称；不伪造完成结果，也不删除证据引用。
- 完成消息保持第一人称，允许偶尔使用一个 Emoji。
- 错误消息由员工第一人称说明遇到的问题和当前影响；人工接管与审批仍由幕僚长说明。

## 语气规则

- 使用“好呀、没问题、收到、我来看看、交给我”等自然语气词。
- 每条只使用一种语气词；Emoji 每条最多一个，不要求每条都有。
- 不使用撒娇、网络黑话或过量标点。
- 员工必须使用“我”描述自己的动作；不得用“某某已入场”“由 Executor 执行”等第三人称技术播报。
- 四个角色保持轻微差异：线索猎人敏锐直接，数据分析师清晰稳妥，内容策划有想法，销售顾问热情可靠。

## 数据与展示边界

- Gateway/demo timeline 继续产生完整协议事件，任务状态、证据链和故障恢复不变。
- UI 通过纯函数生成用户可见话术，方便真实 Gateway 继续复用。
- Executor、Skill、会话 ID 可以保留在开发数据中，但员工进场、接单、开工气泡不向用户显示。
- 进度卡仍可显示必要的业务步骤和状态，不显示内部协议标题。

## 验收标准

- 四位员工均有不同的第一人称进场话术。
- 进场话术包含自然语气词，并至少有部分话术包含单个 Emoji。
- 用户可见标题和正文不含 `SUB_START`、`Executor`、`Agent 已接受任务`、会话 ID。
- 每个技能开始阶段只出现一个员工气泡。
- 过程和完成反馈均使用第一人称。
- 对话与运行时现有自动化测试通过。

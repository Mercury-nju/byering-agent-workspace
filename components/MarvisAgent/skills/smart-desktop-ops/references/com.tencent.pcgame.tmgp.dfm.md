# 三角洲行动 桌面应用操作规范

## 0. 应用概述

**应用类型**：native（原生 Windows 应用）

注意：`name_cue(action="launch")`仅能启动三角洲行动启动器，后续需要通过启动器启动游戏。

⚠️ **第一人称视角场景终止规则**：如果在任何操作过程中检测到进入了游戏内第一人称视角场景（FPS 视角：可见武器模型、准心、HUD 等），**立即停止所有后续操作，直接输出操作结果报告**。不需要在第一人称视角场景内执行任何操作。

**窗口特征**：
- **启动器窗口**：独立窗口，顶部有标签导航栏（首页、黑鹰坠落等模式标签），右下方有醒目的红色"开始游戏"按钮，窗口中央为活动推广/新闻公告区域
- **游戏主体窗口**：启动器点击"开始游戏"后加载，游戏主体为独立全屏或窗口化界面，加载过程可能较长（15-60 秒），期间会显示加载画面
- 启动器和游戏主体是**两个独立进程**，进入游戏后启动器窗口会自动隐藏
- **游戏主体进程名**：`DeltaForceClient-Win64-Shipping.exe`（用于进程检测和窗口截图匹配）

⚠️ 三角洲行动的启动器和游戏主体是分离的：先启动 Launcher，再通过 Launcher 的"开始游戏"按钮加载游戏主体。两者加载时间均较长，需要充足的等待时间。

## 0.1 参数规则

**本 App 固定窗口名**（不同阶段窗口名不同，详见 SKILL.md 参考表）：
- 启动器阶段：`app_name="delta_force_launcher"`
- 游戏主体阶段：`app_name="DeltaForceClient-Win64-Shipping"`

**App 特有规则**：
1. **严格禁止使用 `exe_capture_screen`**（覆盖通用规范）：所有操作必须围绕 `exe_capture_window` / `exe_dump_ui` 展开。

## 1. 核心操作流程

### 1.1 启动游戏并进入大厅

```
打开三角洲行动
  ├─ exe_open_shortcut 启动启动器（路径见 §0）
  ├─ wait 等待启动器加载（8000ms）
  ├─ exe_capture_window(app_name="delta_force_launcher") 确认启动器界面已就绪
  │   └─ 如需定位文字按钮，紧接着使用 exe_dump_ui(app_name="delta_force_launcher") 获取 OCR 坐标
  ├─ 处理可能出现的公告/活动弹窗（见 §4.1）
  ├─ 🔴 【关键步骤】检测启动器是否显示"更新游戏"（见 §4.2 游戏更新检测与处理）
  │   ├─ exe_dump_ui(app_name="delta_force_launcher") 查找"更新""更新游戏""下载"等关键词
  │   ├─ 如果发现"更新游戏"按钮 → 按 §4.2 点击更新并等待完成
  │   ├─ 如果发现更新进度条 → 按 §4.2 轮询等待更新完成
  │   └─ 如果显示正常的"开始游戏"按钮 → 无需更新，继续下一步
  ├─ ⚠️ 【关键步骤】点击"开始游戏"按钮（见 §1.3 点击操作规范）
  │   ├─ 精确定位按钮坐标 → exe_action_pipeline 一次性完成
  │   └─ 点击后 exe_capture_window 验证按钮是否被点击成功
  ├─ 🔴 【关键步骤】检测游戏主体进程是否启动（见 §1.4 游戏主体进程检测）
  │   ├─ wait 15000ms（给游戏主体充足的启动时间）
  │   ├─ exe_capture_window(app_name="DeltaForceClient-Win64-Shipping") 直接截图检测游戏主体窗口
  │   │   ├─ ✅ 截图成功 → 🎯 **游戏主体已启动，启动任务完成（见 §1.5 启动成功判定）**
  │   │   └─ ❌ 截图失败 → 每隔 10 秒重新尝试截图，最多重试 6 次（共约 75 秒）
  │   └─ 如果窗口始终无法截图（超过 75 秒）→ 回到启动器检查状态，可能需要重新点击"开始游戏"
  │
  └─ ✅ 截图确认 `DeltaForceClient-Win64-Shipping.exe` 窗口存在 → 启动任务结束，输出操作结果（见 §5）
```

### 1.2 注意事项

- 游戏启动和加载时间较长，启动器加载约 5-10 秒，游戏主体加载约 15-60 秒，需耐心等待
- 游戏更新时启动器会显示"更新游戏"按钮或下载进度条而非"开始游戏"按钮，此时需先点击更新并等待更新完成（见 §4.2）
- 进入游戏后界面为 3D 渲染画面，UI 元素样式与传统桌面应用不同，需要视觉识别游戏内 UI
- 游戏内操作响应可能有延迟，点击后建议等待 1-2 秒再截图验证
- 🔴 **如果在任何阶段检测到第一人称视角场景，立即停止操作并输出结果报告，不做任何场景内操作**

⚠️ 游戏加载过程中请勿频繁操作，等待加载画面消失后再进行下一步。

### 1.3 截图与点击操作规范（⚠️ 必读）

🔴🔴 **本节为三角洲行动操作的核心规范，所有需要截图定位 + 鼠标点击的操作都必须严格遵循此流程。**

#### 1.3.1 App 特有操作原则

1. **必须使用 `exe_action_pipeline` 一次性完成移动+等待+点击**，禁止分开调用 `exe_mouse(mouse_action="move")` 和 `exe_mouse(mouse_action="click")`（分开调用可能导致焦点丢失，点击不生效）。
2. **每次点击后必须 `exe_capture_window` 截图验证**，确认操作生效。
3. **`app_name` 选择规则**：
   - 启动器阶段：`app_name="delta_force_launcher"`
   - 游戏主体阶段：`app_name="DeltaForceClient-Win64-Shipping"`
   - 如果匹配到多个窗口（Multiple windows match），使用更精确的进程名

#### 1.3.2 标准点击流程

```
步骤 1：exe_capture_window(app_name=...) 获取窗口截图
步骤 2：文字按钮优先 exe_dump_ui；OCR 未命中则回退到窗口截图 + gui_grounder
步骤 3：exe_action_pipeline 一次性执行（move → wait 300ms → click），传入正确的 source 和 app_name
步骤 4：wait 等待操作生效（2000-10000ms）
步骤 5：exe_capture_window 截图验证 → 未生效则按 §1.3.3 重试
```

#### 1.3.3 点击失败重试策略

点击后截图验证发现界面未发生预期变化时，按通用规范「点击失败反思」执行。以下为本 App 特有补充：

```
重试流程（最多重试 2 次）
  ├─ 第 1 次重试：先点击窗口空白区域确保窗口获得焦点，wait 500ms，重新定位并点击
  │
  ├─ 第 2 次重试：尝试双击
  │   ├─ 重新使用 exe_capture_window + gui_grounder 定位
  │   └─ exe_action_pipeline: move → wait 300ms → click (click_count=2)
  │
  └─ 仍然失败 → 报告用户
```

#### 1.3.4 焦点管理（⚠️ 三角洲特有问题）

三角洲行动启动器是自定义 UI 框架窗口，存在焦点管理特殊行为：

1. **`window_x/y` 为 `-32000` 表示窗口最小化/隐藏**：启动器点击"开始游戏"后会自动隐藏，需通过进程检测确认状态（见 §1.4）
2. **点击前确保窗口激活**：先用 `exe_action_pipeline` 点击一次窗口非按钮区域（如标题栏或空白区域），确保窗口获得焦点

### 1.4 游戏主体进程检测

🔴 **点击"开始游戏"后，必须通过检测 `DeltaForceClient-Win64-Shipping.exe` 进程来确认游戏主体是否成功启动，而非仅依赖启动器界面状态判断。**

⚠️ 启动器点击"开始游戏"后会自动隐藏（`window_x/y` 变为 `-32000`），但这**不代表游戏主体已成功启动**。`query_apps(query_type="running")` 可能只返回安卓应用列表，对 Windows 进程检测无效，因此**以 `exe_capture_window` 直接截图验证为主要检测手段**。

```
点击"开始游戏"按钮后
  ├─ wait 15000ms（等待游戏主体进程启动，游戏主体初始化较慢）
  │
  ├─ 🔍 【主要方式】直接窗口截图检测（循环检测）
  │   ├─ exe_capture_window(app_name="DeltaForceClient-Win64-Shipping") 尝试截图游戏主体窗口
  │   │   ├─ ✅ 截图成功 → 🎯 **游戏主体已启动，启动任务完成（见 §1.5 启动成功判定）**
  │   │   └─ ❌ 截图失败（No window found）→ 游戏主体尚未启动或窗口不可见
  │   │       ├─ wait 10000ms → 再次尝试 exe_capture_window 截图
  │   │       └─ 最多重试 6 次（首次等待 15s + 6×10s = 共约 75 秒）
  │
  └─ ⏰ 超时处理（窗口始终无法截图，75 秒后）
      ├─ exe_capture_window(app_name="delta_force_launcher") 截图启动器检查状态
      │   ├─ 启动器显示"开始游戏"按钮 → 游戏主体启动失败，需重新点击"开始游戏"
      │   ├─ 启动器显示更新进度 → 游戏正在更新，转入 §4.2 游戏更新等待
      │   └─ 启动器窗口不可见 → 启动器可能已崩溃，需重新启动（§4.6）
      └─ 重试一次仍无效则告知用户
```

### 1.5 启动成功判定（⚠️ 启动任务完成标准）

🔴 **启动任务的完成标准：`exe_capture_window(app_name="DeltaForceClient-Win64-Shipping")` 截图成功即视为游戏启动成功，启动任务结束。**

- **成功条件**：`exe_capture_window(app_name="DeltaForceClient-Win64-Shipping")` 能够成功截取到游戏主体窗口（无论截图内容是加载画面、游戏大厅还是其他界面）
- **判定逻辑**：截图成功 = 游戏主体进程 `DeltaForceClient-Win64-Shipping.exe` 已启动且窗口已创建 = 启动任务完成
- **无需等待加载完成**：不需要等待游戏完全加载到大厅界面，只要窗口存在即可结束启动任务
- **输出结果**：确认截图成功后，直接输出操作结果报告（见 §5），标注启动成功

## 4. 特殊场景处理

### 4.1 活动公告弹窗处理

🔴 **弹窗处理首选方案：按 `Esc` 键关闭**。无论在启动器阶段还是游戏大厅/烽火地带内，遇到活动公告弹窗时，**优先按 `Esc` 键**而非尝试寻找并点击关闭按钮。

三角洲行动在启动器启动后、进入游戏大厅后都可能弹出活动公告弹窗，需自动处理：

⚠️⚠️ **特别注意弹窗处理**
- 弹窗可能在各种界面切换后弹出，这是最常见的卡点
- 此时必须**优先按 `Esc` 键关闭弹窗**，不要将弹窗覆盖的界面误判为其他正常界面
- 可能连续出现多个弹窗（关闭一个后又弹出另一个），需要**反复按 `Esc` + 截图确认**直到所有弹窗全部关闭
- 只有在确认弹窗全部关闭后，才能继续后续操作

**弹窗识别特征**：
- 界面上方覆盖了一个浮层/弹窗，四周有暗色半透明遮罩
- 弹窗内容通常为活动推广、皮肤捆绑包、赛季公告等
- 弹窗底部可能有"前往参与"等按钮

**处理流程**：
```
发现活动公告弹窗
  ├─ 🔴 优先方案：按 Esc 键关闭（循环处理直到弹窗全部消失）
  │   ├─ exe_press_key(key_name="escape")
  │   ├─ wait 2000ms
  │   └─ exe_capture_window 截图确认弹窗已关闭
  │       ├─ 弹窗已关闭且无新弹窗 → 继续正常流程
  │       ├─ 出现新的弹窗 → 再次按 Esc → 再截图确认（最多循环 5 次）
  │       └─ 同一弹窗仍在（Esc 无效）→ 执行备选方案
  │
  └─ 备选方案（Esc 无效时）：查找关闭按钮点击
      ├─ 查找弹窗右上角的 × 关闭按钮
      ├─ 或查找"关闭"/"确认"/"我知道了"按钮
      ├─ 对文字按钮优先用 exe_dump_ui，执行时传 source="ocr" + app_name
      ├─ 对非文字按钮回退到 exe_capture_window + `gui_grounder` ，执行时传 source="window" + app_name
      └─ 截图确认弹窗已关闭
```

**其他类型弹窗**：
- **版本更新提示**：如启动器显示"更新游戏"按钮或更新进度条，按 §4.2 流程处理（先点击更新，等待完成后再点击"开始游戏"）
- **授权弹窗**：如出现"授权QQ好友关系"等复选框弹窗，按 Esc 键关闭或查找关闭按钮
- **防沉迷提示**：如出现防沉迷相关提示，查找确认/关闭按钮处理

### 4.2 游戏更新检测与处理

⚠️ 游戏有版本更新时，启动器的"开始游戏"按钮会变为"更新游戏"按钮（或类似的"更新""下载更新"文字），此时必须先点击更新按钮并等待更新完成，才能点击"开始游戏"进入游戏。

#### 4.2.1 更新状态识别

**更新状态识别特征**（通过 `exe_dump_ui` OCR 识别）：
- **需要更新**：OCR 识别到"更新游戏""更新""下载更新"等文字出现在原"开始游戏"按钮位置（启动器右下方区域）
- **正在更新中**：OCR 识别到下载进度百分比（如"45%""下载中"）、下载速度（如"12.5MB/s"）、或显示水平进度条
- **更新完成**：更新进度消失，"开始游戏"按钮重新出现
- **无需更新**：正常显示"开始游戏"按钮

#### 4.2.2 更新处理流程

```
启动器截图 + OCR 文字识别后
  │
  ├─ 情况 A：发现"更新游戏"按钮（需要点击启动更新）
  │   ├─ 优先使用 exe_dump_ui 获取"更新游戏"文字中心坐标
  │   ├─ 通过 exe_action_pipeline 点击，正确传入 source 和 app_name
  │   ├─ wait 3000ms（等待更新开始）
  │   ├─ exe_capture_window(app_name="delta_force_launcher") 截图验证
  │   │   ├─ 出现下载进度条/百分比 → 更新已开始，转入"情况 B"等待更新完成
  │   │   ├─ 界面未变化 → 点击可能未生效，按 §1.3.5 重试策略重试点击
  │   │   └─ 出现弹窗（如磁盘空间不足等提示）→ 告知用户处理
  │   └─ 进入更新等待轮询（情况 B）
  │
  ├─ 情况 B：正在更新中（显示下载进度条/百分比）
  │   ├─ 每隔 15 秒 exe_capture_window(app_name="delta_force_launcher") 截图 + exe_dump_ui 检查进度
  │   ├─ 从 OCR 结果中提取进度百分比和下载速度（如有）
  │   │   ├─ 进度持续增长 → 更新正常进行，继续等待
  │   │   ├─ 进度长时间未变化（连续 3 次截图进度相同，约 45 秒）→ 可能下载卡住
  │   │   │   └─ 告知用户当前状态，建议检查网络
  │   │   └─ 进度达到 100% 或进度条消失 → 更新可能已完成，截图确认
  │   ├─ 更新完成判断：
  │   │   ├─ "开始游戏"按钮重新出现 → ✅ 更新完成，继续 §1.1 主流程点击"开始游戏"
  │   │   └─ 出现"需要重启启动器"等提示 → 按提示操作，或关闭后重新 exe_open_shortcut 启动
  │   └─ 大版本更新可能耗时较长（数分钟到数十分钟），如预估剩余时间超过 5 分钟，告知用户等待
  │
  └─ 情况 C：无需更新（正常显示"开始游戏"按钮）
      └─ 跳过更新流程，继续 §1.1 主流程点击"开始游戏"
```

### 4.3 游戏加载超时

- 点击"开始游戏"后正常加载时间为 15-60 秒
- 先通过 `exe_capture_window(app_name="DeltaForceClient-Win64-Shipping")` 直接截图检测游戏主体窗口是否存在（见 §1.4）
- 窗口截图成功后，每隔 10 秒 `exe_capture_window(app_name="DeltaForceClient-Win64-Shipping")` 截图检查是否仍在加载画面
- 如超过 90 秒仍未进入大厅，可能遇到卡加载，尝试 `alt+f4` 关闭后重新启动
- 重试一次仍无效则告知用户

### 4.6 启动器窗口焦点丢失

- `exe_capture_window` 返回错误（找不到窗口）→ 启动器已崩溃，重新 `exe_open_shortcut` 启动
- `window_x/y` 为 -32000 → 窗口已最小化（可能是"开始游戏"后隐藏行为），参考 §1.4 进程检测

### 4.7 游戏内第一人称视角场景（终止规则）

🔴 **如果在任何阶段的截图中检测到第一人称视角游戏内场景，立即停止所有后续操作，直接输出操作结果报告。**

**第一人称视角场景识别特征**：
- 画面呈现 FPS 第一人称视角：可见武器模型（枪械/刀具）、准心/十字瞄准线
- 3D 室内或室外环境（如基地、训练设施、科幻风格房间等）
- 画面底部或角落可能有 HUD 信息（血量、护甲值、弹药数等）
- **没有大厅的模式选择 UI**（没有"烽火地带""全面战场"等入口按钮）

**处理方式**：
```
检测到第一人称视角游戏内场景
  └─ 🔴 立即停止所有后续操作
      └─ 输出操作结果报告（见 §5），标注当前位置为"游戏内第一人称视角场景"
```

⚠️ **不需要在第一人称视角场景内执行任何操作**（不需要按 Tab、不需要按 Esc、不需要寻找导航入口）。检测到即终止，直接输出结果。

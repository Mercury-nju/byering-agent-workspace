# 项目复盘模板

## 章节结构

### 第1章 复盘概要
- **写作要点指导**：用一段话概述项目基本信息（项目名称、时间周期、参与团队）、项目核心目标与最终结果。使用表格呈现关键指标的目标值 vs 实际值。给出总体评价（达成/部分达成/未达成）

### 第2章 项目目标与范围回顾
- **写作要点指导**：回顾项目启动时的原始目标与范围定义，记录项目过程中的范围变更（如有），对比最终交付范围与初始计划的差异，分析范围变化的原因与影响

### 第3章 执行过程回顾
- **写作要点指导**：按时间线梳理项目关键里程碑与实际执行情况（使用表格对比计划 vs 实际），识别执行过程中的关键转折点与重要决策，分析进度偏差的根因

### 第4章 成果与亮点（做得好的）
- **写作要点指导**：系统总结项目中做得好的方面（技术创新、流程优化、团队协作等），分析成功因素，提炼可复用的最佳实践。每个亮点要有具体事例支撑

### 第5章 问题与教训（做得不好的）
- **写作要点指导**：诚实记录项目中遇到的问题与踩坑经历，使用"5 Why"等方法进行根因分析（不停留在表面），评估问题的影响程度，总结应该如何避免/更好地处理

### 第6章 改进建议
- **写作要点指导**：针对第5章识别的每个问题，给出具体的改进措施。区分短期改进（立即可行动）和长期改进（需要资源/制度支持）。使用表格呈现：问题→改进措施→负责人→时间节点

### 第7章 经验沉淀与知识传承
- **写作要点指导**：将复盘中提炼的关键经验/教训，凝练为可复用的方法论或checklist，明确知识传承方式（文档归档、团队分享、培训等），列出后续需要跟踪的改进事项

## 写作要求
- 语言风格：半正式，坦诚客观，问题导向而非指责导向
- 数据要求：关键结论必须有数据支撑（如延期天数、缺陷率、效率提升等）；里程碑进度使用表格对比
- 特殊约束：遵循"对事不对人"原则；问题分析要深入根因，避免停留在"下次注意"层面；改进建议必须具体可执行，有负责人和时间节点
